# 빈틈의실 UI 고도화

2026-11-08. `codex/ui-refinement` 브랜치의 네이티브 Android 화면과 앱 소유 웹 콘텐츠를 함께 개편했다.

## 화면과 테마

| 항목 | 적용 내용 |
| --- | --- |
| 화면 모드 | 자동·라이트·다크. 설정 화면에서 선택하며 앱을 다시 열어도 선택을 유지한다. 자동은 Android의 야간 모드 설정을 따른다. 상단 해/달 버튼으로 직접 전환할 수도 있다. |
| 라이트 | 따뜻한 오프화이트 바탕, 흰 카드, 차콜 본문, 라임 강조 |
| 다크 | 차콜 바탕, 서로 다른 명도의 패널, 밝은 본문, 라임 강조 |
| 충전 요약 | 자동차 장식 대신 270도 SOC 게이지, 큰 잔량 숫자, 상태, 대기시간을 배치했다. 숫자가 없으면 게이지의 중립 트랙만 표시한다. |
| 대시보드 | 활동 종류를 나타내는 아이콘, 소요시간, 짧은 설명, 시작 버튼으로 정리했다. 준비가 끝난 뒤 남아 있던 ‘차량 상태 확인 중’ 문구를 제거했다. |
| 미디어 | 공식 예제 영상·60초 눈 휴식 카드와 현재 콘텐츠·다시 열기·닫기를 구분했다. 앱 소유 HTML도 같은 팔레트를 쓴다. YouTube 자체 플레이어 디자인은 변경하지 않는다. |
| 설정 | 화면 모드, 좋아하는 활동·취향 기억, 차량 연결을 카드로 나눴다. 개발용 진단·시나리오는 펼쳐서 볼 수 있다. |
| 탐색 | 대시보드·미디어·설정에 동일한 원본 선형 아이콘과 선택 상태를 적용했다. 좁은 창에서는 아이콘을 글자 위에 배치한다. |

공통 팔레트는 `app/src/main/java/com/binteum/app/ui/AppTheme.kt`, 아이콘은 `IconDrawable.kt`, 게이지는 `ChargeGaugeView.kt`가 담당한다. 외부 이미지·아이콘 폰트를 다운로드하지 않는다. 앱의 테마는 Pleos 런처·차량 기본 패널의 색상을 변경하지 않는다.

## 반응형 배치와 가독성

- 앱 창 1100dp 이상: 충전 패널 폭 320/350dp를 확보하고 콘텐츠를 오른쪽에 표시한다. 시간 선택은 2×2로 배치한다.
- 1100dp 미만: 충전 요약을 압축하고 목표·시간 설정을 접을 수 있게 한다. 활동을 보기 전에 큰 자동차 그림이나 모든 설정을 지나가지 않아도 된다.
- 활동 카드: 사용할 수 있는 콘텐츠 폭을 기준으로 1/2/3열을 정한다. 2열에서 마지막 한 장의 높이가 축소되지 않도록 빈 칸도 같은 측정 계약을 사용한다.
- 미디어 카드: 실제 패널 폭 800dp 이상에서 2열, 그보다 작으면 1열이다.
- 버튼 최소 높이 64dp, 주요 메뉴 최소 높이 72dp. 문구가 길거나 글자가 커지면 높이를 늘린다. 비활성·선택·키보드 포커스 상태를 구분한다.
- 팔레트 계산상 본문·보조 텍스트 대비의 최저값은 라이트 4.71:1, 다크 7.42:1이다. 강조 배경 위에는 전용 어두운 글자색을 쓴다. 이는 화면 밝기·반사·실차 가독성 검증을 대신하지 않는다.

## 동작 유지와 검증

테마 변경은 차량 세션·타이머·취향 설정을 초기화하지 않는다. 시스템 테마나 창 크기 변경도 화면만 다시 배치한다. 현재 허용된 미디어 패널의 동기 재배치에는 명시적 범위를 두어 불필요한 WebView 파기를 피한다. 테마 CSS 갱신은 페이지를 다시 로드하거나 재생 명령을 보내지 않는다. 실제 탭 이탈·안전 차단·Activity 중지는 기존처럼 콘텐츠를 파기한다.

core 테스트 23개 통과, debug APK 빌드 성공, lint 오류 0개·기존 버전 안내 경고 3개를 확인했다. 이 테스트는 충전·추천 로직 검증이며 UI 픽셀 검증이 아니다. 두 웹 콘텐츠의 JavaScript 구문 검사와 코드 검토를 수행했다. 기기 실행에서 발견한 초기 시스템 바 설정 순서 오류를 수정한 뒤 Pleos API 34 에뮬레이터 설치·콜드 실행·프로세스 유지와 해당 실행의 크래시 로그 없음을 확인했다. 최종 기기 확인 항목은 다음과 같다.

2026-11-08 사용자가 설치된 Pleos 에뮬레이터에서 라이트·다크를 전환한 뒤 **두 모드 모두 화면이 정상 표시됨**을 확인했다. 사용자 관찰에 따른 확인이며, 모든 화면 크기와 재생 중 전환까지 검증한 것으로 확대하지 않는다.

남은 확인 항목:

1. 자동 모드의 시스템 설정 반영, 앱 재시작 후 선택 유지.
2. 대시보드·미디어·설정에서 글자·아이콘·버튼의 명암과 잘림 여부.
3. 1/2/3열 및 100% SOC, 글자 크기 확대에서 겹침 여부.
4. 진행 중 활동의 테마 변경 시 타이머 유지.
5. 미디어의 탭 이탈·제한 전환 시 중지. 테마 변경 중 재생 유지는 아래 사용자 확인 기록을 참고한다.

독립 에뮬레이터 창은 현재 UI 제어 도구에서 인식되지 않으므로, 기기 화면의 시각 확인 결과는 코드/빌드 검증과 구분해 기록한다.

## 사용자 화면에서 확인한 배치 수정

이후 제공된 화면에서 SOC 숫자와 ‘현재 배터리’ 설명이 게이지 왼쪽에 겹치는 문제가 확인됐다. 부모 레이아웃의 중앙 정렬만 적용되어 있었고, 가로 전체를 차지하는 TextView 자체는 왼쪽 정렬이었다. 두 TextView를 각각 중앙 정렬하고, 텍스트 묶음을 원호 안의 폭으로 제한해 가운데 배치했다. SOC는 한 줄로 유지하며 폭에 맞춰 크기를 조정한다.

글자 배율 1.3 이상에서는 원형 게이지 대신 SOC·상태를 세로로 표시하고 목표·시간 선택도 세로로 배치한다. 아주 좁은 창의 SOC와 상태 역시 세로 배치한다. 텍스트를 원호나 옆 문구에 억지로 맞추지 않는다.

시간이 끝난 화면은 추천 제목·마무리 설명의 중복을 없애고 ‘현재 선택한 시간으로 새로 설정’과 ‘다른 시간 선택’을 제공한다. 미디어에도 같은 종료 상태를 적용한다. 남은 시간에 따라 활동 가능 여부와 2분·0초 경계가 바뀌면 해당 화면을 다시 평가한다. 새 시간은 사용자의 명시적인 선택으로만 시작 준비하며 기존 시간 예산을 자동 연장하지 않는다.

테마 변경 시 충전 패널과 콘텐츠의 스크롤 위치를 복원한다. 미디어에서는 활동 추천의 길이 경계만 바뀌었다는 이유로 패널을 재배치하지 않는다. 실제 재생 유지 확인은 코드 검토와 구분한다.

2026-11-08 수정본 설치 후, 사용자가 게이지 중앙 정렬과 영상 재생 중 해·달 버튼 전환을 확인하고 ‘정렬도 맞고 재생도 유지돼’라고 응답했다. 영상·소리·스크롤 위치를 함께 확인하도록 요청한 결과다. 해당 Pleos 에뮬레이터에서의 사용자 확인이며, 작은 창·큰 글자·실차 및 주행 제한 전환 검증과는 구분한다.
