# 빈틈의실 UI 고도화

## 현재 화면 — 2026-11-10 충전 정보 기반 대시보드

`codex/charge-aware-dashboard`에서 형의 `codex/refactor-ui` 디자인을 바탕으로 화면 역할을 다시 나눴다. **이 절이 현재 동작을 설명하며, 아래 타이머·통합 홈·영상 전용 홈 설명은 이전 단계의 기록이다.**

- 충전 패널은 현재 SOC 게이지, 목표까지 남은 예상 충전시간, 값의 출처, 앱/차량 목표, 선택적 출발 시각을 표시한다. 시간을 먼저 고르고 ‘확인’을 눌러야 콘텐츠가 열리는 흐름은 제거했다.
- OEM ETA는 목표가 맞고 유효한 경우에만 사용한다. 최근 SOC 증가로 계산한 값은 근사치라고 표시한다. 모르는 시간을 임의의 20분이나 0분으로 채우지 않는다. 출발 시각은 충전 ETA와 다른 항목이다.
- 앱 추천 목표 선택과 차량의 실제 충전 한도 변경을 분리했다. 실제 변경은 지원·권한·안전 조건을 확인한 경우의 명시적 조작이며 readback 확인이 필요하다. 실제 쓰기 검수는 아직 하지 않았다.
- 하단 **대시보드 / 영상 / 활동** 탭을 제공한다. 대시보드는 충전시간·충전량·축적한 선택에 맞는 후보를 최대 3개 추천한다. 영상과 활동 탭에서는 추천 없이 직접 고른다.
- ETA가 없거나 원하는 콘텐츠가 남은 시간보다 길어도 직접 선택할 수 있다. 시간 적합성 안내는 유지하며, 충전 중단·안전 미확인·주행 제한·앱 이탈에 대한 실행/재생 차단은 유지한다.
- 활동 탭에 눈 휴식·생각 정리·퀴즈·호흡·명상을 복원했다. 자체 활동의 진행 타이머와 충전 예상시간은 다른 정보다.
- 설정에서 선택 기록 수와 최근 기록을 확인하고 추천 반영을 켜거나 끌 수 있다. 반영을 꺼도 선택 기록은 계속 저장한다. 전체 삭제는 기록과 자체 활동 평가를 함께 지운다. 시연 기록은 표시를 붙이고 실제 선호도 계산에서 제외한다.
- 시간대별 배경, 단색 블랙/화이트, 패널 좌우 이동, 글자 크기와 언어 설정은 유지했다. 음성 설정은 **실험용 미리 듣기**이며 충전 완료 안내가 작동한다는 의미가 아니다.

core 58개와 에뮬레이터 기록 검사 8개를 통과했고 debug 빌드·lint 오류 0개를 확인했다. 새 APK를 에뮬레이터에 설치·실행했다. 실제 기기 화면·터치·재생 검수는 사용자 확인을 요청한 상태다. 이전 버전의 사용자 확인을 이번 화면의 검수 완료로 확대하지 않는다.

## 반응형 배치와 가독성

- 앱 창 1100dp 이상: 충전 패널 폭 320/350dp를 확보하고 콘텐츠를 오른쪽에 표시한다. 시간 선택은 2×2로 배치한다.
- 1100dp 미만: 충전 요약을 압축하고 목표·시간 설정을 접을 수 있게 한다. 활동을 보기 전에 큰 자동차 그림이나 모든 설정을 지나가지 않아도 된다.
- 활동 카드: 사용할 수 있는 콘텐츠 폭을 기준으로 1/2/3열을 정한다. 2열에서 마지막 한 장의 높이가 축소되지 않도록 빈 칸도 같은 측정 계약을 사용한다.
- 미디어 카드: 실제 패널 폭 800dp 이상에서 2열, 그보다 작으면 1열이다.
- 버튼 최소 높이 64dp, 주요 메뉴 최소 높이 72dp. 문구가 길거나 글자가 커지면 높이를 늘린다. 비활성·선택·키보드 포커스 상태를 구분한다.
- 팔레트 계산상 본문·보조 텍스트 대비의 최저값은 라이트 4.71:1, 다크 7.42:1이다. 강조 배경 위에는 전용 어두운 글자색을 쓴다. 이는 화면 밝기·반사·실차 가독성 검증을 대신하지 않는다.

## 동작 유지와 검증

테마 변경은 차량 세션·타이머·취향 설정을 초기화하지 않는다. 시스템 테마나 창 크기 변경도 화면만 다시 배치한다. 현재 허용된 미디어 패널의 동기 재배치에는 명시적 범위를 두어 불필요한 WebView 파기를 피한다. 테마 CSS 갱신은 페이지를 다시 로드하거나 재생 명령을 보내지 않는다. 실제 탭 이탈·안전 차단·Activity 중지는 기존처럼 콘텐츠를 파기한다.

core 테스트 23개 통과, debug APK 빌드 성공, lint 오류 0개·기존 버전 안내 경고 3개를 확인했다. 이 테스트는 충전·추천 로직 검증이며 UI 픽셀 검증이 아니다. 두 웹 콘텐츠의 JavaScript 구문 검사와 코드 검토를 수행했다. 기기 실행에서 발견한 초기 시스템 바 설정 순서 오류를 수정한 뒤 Pleos API 34 에뮬레이터 설치·콜드 실행·프로세스 유지와 해당 실행의 크래시 로그 없음을 확인했다. 최종 기기 확인 항목은 다음과 같다.

2026-11-08 사용자가 설치된 Pleos 에뮬레이터에서 라이트·다크를 전환한 뒤 **두 모드 모두 화면이 정상 표시됨**을 확인했다. 사용자 관찰에 따른 확인이며, 모든 화면 크기와 재생 중 전환까지 검증한 것으로 확대하지 않는다.

남은 확인 항목:

1. 자동 모드의 시스템 설정 반영, 앱 재시작 후 선택 유지.
2. 대시보드·미디어·설정에서 글자·아이콘·버튼의 명암과 잘림 여부.
3. 1/2/3열 및 100% SOC, 글자 크기 확대에서 겹침 여부.
4. 진행 중 활동의 테마 변경 시 타이머 유지.
5. 미디어의 탭 이탈·제한 전환 시 중지. 테마 변경 중 재생 유지는 아래 사용자 확인 기록을 참고한다.

독립 에뮬레이터 창은 현재 UI 제어 도구에서 인식되지 않으므로, 기기 화면의 시각 확인 결과는 코드/빌드 검증과 구분해 기록한다.

## 사용자 화면에서 확인한 배치 수정

이후 제공된 화면에서 SOC 숫자와 ‘현재 배터리’ 설명이 게이지 왼쪽에 겹치는 문제가 확인됐다. 부모 레이아웃의 중앙 정렬만 적용되어 있었고, 가로 전체를 차지하는 TextView 자체는 왼쪽 정렬이었다. 두 TextView를 각각 중앙 정렬하고, 텍스트 묶음을 원호 안의 폭으로 제한해 가운데 배치했다. SOC는 한 줄로 유지하며 폭에 맞춰 크기를 조정한다.

글자 배율 1.3 이상에서는 원형 게이지 대신 SOC·상태를 세로로 표시하고 목표·시간 선택도 세로로 배치한다. 아주 좁은 창의 SOC와 상태 역시 세로 배치한다. 텍스트를 원호나 옆 문구에 억지로 맞추지 않는다.

시간이 끝난 화면은 추천 제목·마무리 설명의 중복을 없애고 ‘현재 선택한 시간으로 새로 설정’과 ‘다른 시간 선택’을 제공한다. 미디어에도 같은 종료 상태를 적용한다. 남은 시간에 따라 활동 가능 여부와 2분·0초 경계가 바뀌면 해당 화면을 다시 평가한다. 새 시간은 사용자의 명시적인 선택으로만 시작 준비하며 기존 시간 예산을 자동 연장하지 않는다.

테마 변경 시 충전 패널과 콘텐츠의 스크롤 위치를 복원한다. 미디어에서는 활동 추천의 길이 경계만 바뀌었다는 이유로 패널을 재배치하지 않는다. 실제 재생 유지 확인은 코드 검토와 구분한다.

2026-11-08 수정본 설치 후, 사용자가 게이지 중앙 정렬과 영상 재생 중 해·달 버튼 전환을 확인하고 ‘정렬도 맞고 재생도 유지돼’라고 응답했다. 영상·소리·스크롤 위치를 함께 확인하도록 요청한 결과다. 해당 Pleos 에뮬레이터에서의 사용자 확인이며, 작은 창·큰 글자·실차 및 주행 제한 전환 검증과는 구분한다.

## Refactor UI — 2026-11-08 공동개발 환경

브랜치 `codex/refactor-ui`는 공유 기준 `254429c`에서 시작했다. 제공된 참고 이미지의 네이비·보라 그라데이션, 둥근 카드, 살구·라벤더·민트 포인트와 부드러운 입체 도형을 네이티브 UI에 적용했다. 이미지 속 날씨·일정·알람 등의 실제 데이터가 있는 것처럼 표시하지 않는다.

- 설정 진입은 좌측 상단 톱니바퀴로 이동했다. 하단은 대시보드·미디어만 제공한다. 설정 내부의 화면·취향·차량 연결은 펼침 방식이다.
- 왼쪽 충전 열은 배경·팔레트만 변경했다. SOC·상태·목표·시간 선택·재설정과 기존 안전 조건은 유지했다.
- 홈은 인사말, 기분 기록·3분 호흡·3분 명상 카드, YouTube 진입 카드로 구성했다. 기존 눈 쉬기·생각 정리·퀴즈는 ‘다른 활동 둘러보기’에 유지한다.
- 기분 기록은 가장 최근 선택 하나와 날짜만 로컬에 저장하고 오늘 기록만 홈에 표시한다. 카드에서 삭제할 수 있으며 서버 전송·취향 학습에는 쓰지 않는다.
- 호흡·명상은 로컬 안내와 기존 활동 타이머·복구·완료 흐름을 사용한다. 시작에 활동 3분과 마무리 2분이 필요하며 실제 차량 안전 조건을 우회하지 않는다. 의료적 효능을 주장하지 않는다.
- 미디어의 닫기·다시 열기는 필요한 상태에만 표시한다. 재생 중에는 콘텐츠 선택 카드를 감춘다. 테마 변경 시 기존 WebView 재배치/스크롤 복원 경로를 유지한다.
- 권한이 없는 첫 실행에서는 정차 UX 상태 확인 후 배터리 상태 읽기의 목적과 충전 제어를 하지 않는다는 안내를 띄운다. ‘계속’으로 기존 Android 런타임 요청에 연결하고 ‘나중에’도 제공한다. 이미 권한을 허용한 프로필에는 반복 표시하지 않는다.
- 날씨, 캘린더, 알람, 운세, Netflix 추천은 현재 앱에 연결된 데이터·제공자 계약·지원 경로가 없어 이번 구현에서 제외했다.

core에는 직접 선택한 호흡·명상의 300초 경계, 비충전 상태 차단, 복구용 ID 조회·평가 중복 방지 테스트를 추가했다. 기존 추천 순위는 유지한다. 실제 화면의 스타일·정렬과 재생 중 테마 변경, 첫 실행 권한 팝업의 시각 검수는 컴파일·단위 테스트 결과와 구분한다. 기존 설치 프로필에는 에너지 읽기 권한이 이미 있어 새 설치용 안내를 반복해서 띄우기 위해 권한이나 사용자 데이터를 초기화하지 않는다.

### 시간별 배경과 단일 홈 후속 반영

- 대시보드와 미디어를 단일 홈으로 합쳤다. 마음챙김·기존 활동 아래에서 WebView 콘텐츠를 직접 열며 상단 앱 헤더와 하단 탭 바를 제거했다. 설정·테마 조작과 모의 데이터 표시는 기존 왼쪽 충전 패널 안에 배치했다. 차량 OS의 시스템 UI는 변경하지 않는다.
- ‘설정 → 배경 분위기’에서 자동/아침 노을/한낮의 하늘/저녁 노을/고요한 밤을 선택한다. 색 고정과 움직임 켜기·끄기는 별개이며 기기에 저장한다.
- 자동 색은 기기의 현지 시간을 사용한다. 05–07시 밤에서 아침 노을, 07–11시 하늘빛, 11–15시 낮, 15–18시 저녁 노을, 18–21시 밤으로 부드럽게 보간한다. 실제 위치의 일출·일몰이나 날씨를 조회하는 기능은 아니다.
- 배경의 선형·방사형 그라데이션은 120초 주기의 완만한 곡선으로 움직인다. 기존 Drawable과 애니메이션 위상을 화면 재배치 때 유지하며 배경만 무효화한다. 셰이더는 크기/색 변경 때만 생성하고 프레임마다 새 객체나 레이아웃을 만들지 않는다.
- 앱이 비활성화되거나 안전 상태가 확인되지 않으면 움직임을 정지한다. 시스템 애니메이션 비활성화도 따른다. 라이트/다크 문자 가독성을 위해 밝기를 각각 보정한다.
- 통합 홈에서도 WebView 재배치 보존, 활동 시작·설정 진입·안전 제한 시 재생 중지, 남은 시간별 활동 필터와 스크롤 복원 경로를 유지했다.
- 검증: core 29개 통과, debug APK 빌드 성공, lint 오류 0개·기존 버전 안내 경고 3개. 자동 색의 시간 경계·자정 연속성 및 고정 색의 시간 독립성을 테스트했다. 에뮬레이터 현재 프로필에 APK 업데이트와 Activity 실행을 확인했다. 실제 일렁임의 느낌과 화면 배치·영상 재생 중 전환은 사용자 시각 검수 대상이다.

### 다이얼 알림·반투명 패널·문구 단순화

이 절은 위의 기존 충전 열/여러 목표·시간 버튼 설명을 대체한다.

- 왼쪽 패널은 배터리 현재 값, 시간/목표 잔량 토글, 드래그 다이얼, 확인/다시 설정으로 구성한다. 시간은 1–120분, 잔량은 1–100%를 선택한다. 키보드 방향키와 접근성 범위 조절도 지원한다.
- ‘확인’을 눌러야 알림이 시작된다. 시간 모드는 즉시 카운트다운하고 이전 잔량 목표로 종료하지 않는다. 잔량 모드는 목표 숫자와 경과시간을 표시하며 목표 도달 시 경과시간을 고정한다. 두 모드 모두 실제 충전 상태·UX 제한·데이터 신선도 조건을 유지한다.
- 입력 시간은 사용자 알림 시간이다. 실제 OEM 충전 ETA가 없으므로 ‘충전이 완료됩니다’ 대신 ‘후 알림’을 쓴다. 알림은 앱 내 완료 상태 표시이며 백그라운드 알림 서비스나 충전 제어 기능이 아니다.
- 재실행은 같은 부팅의 단조 시계와 저장 체크포인트를 검증한다. 오래된 자동 시작 방식의 체크포인트나 재부팅·시계 불일치는 확인 전 상태로 돌아간다. 다시 설정 시 이전 활동·재생을 종료한다.
- 섹션 배경은 모두 검정 반투명으로 통일했다. 고정 보라색 패널을 제거하고 시간별 배경이 비치도록 했다. 라이트/다크 모두 밝은 글자와 대비가 확보되는 배경 밝기를 사용한다. 선택 상태의 작은 강조색과 콘텐츠 삽화는 유지한다.
- 홈·설정의 감성 인사말, 부제, 완료 후 격려 문구를 제거했다. 기능명·상태·조작 안내만 표시한다. 콘텐츠의 실제 수행 지침과 권한·안전 안내는 유지한다.
- YouTube 샘플은 공식 게시물 메타데이터에서 확인한 Coffee Run(185초, Blender Studio), Big Buck Bunny(635초, Blender)를 사용한다. 시간 모드는 영상 길이+120초가 남은 시간에 들어가는 후보만 표시한다. 잔량 모드는 ETA를 추정하지 않고 ‘시간 미지정’으로 표시한다.

### 활동 메뉴 제외 및 슬라이딩 토글

- 홈에서 기분 기록·눈 휴식·호흡·명상·퀴즈를 제거했다. 미디어의 오프라인 눈 휴식 진입과 설정의 활동 선호 메뉴도 제거했다. 기존 활동 기록은 삭제하지 않지만 앱 재실행 시 이전 활동을 복구하지 않는다. 홈은 영상만 제공한다.
- 시간/목표 잔량은 하나의 슬라이딩 토글이다. 선택 배경은 240ms 동안 이동하고 다이얼 값은 220ms 동안 전환한다. 화면을 재생성하지 않고 값을 갱신하며 시스템 애니메이션 비활성화를 따른다.
- 버튼·선택 토글의 라벤더 채움을 반투명 검정으로 교체했다. 게이지는 선택된 배경 분위기의 중간색과 밝은 중립색을 혼합해 표시하며 시간/배경 설정 변경에 따라 갱신한다.

### 설정 UI와 패널 위치

- 설정의 일반 항목은 접힌 버튼 목록 대신 화면 및 배치/배경/차량 연결 카드에 설명과 현재 값을 항상 표시한다. 선택 항목은 라디오 선택창, 움직임과 모의 충전은 스위치를 사용한다. 개발용 진단만 접어서 보관한다.
- ‘화면 및 배치 → 조작 패널 위치’에서 왼쪽/오른쪽을 선택하고 기기에 저장한다. 넓은 화면에서 패널과 콘텐츠의 배치 순서 및 여백을 반전한다. 좁은 화면의 세로 배치는 유지하며 설정 설명에 이를 명시한다.
- 추천 영역 상단에 남은 시간을 초 단위로 갱신하고 추천 개수를 표시한다. ‘영상 길이 + 마무리 2분’ 기준을 표시하며 광고/로딩을 별도로 안내한다. 목표 잔량 모드는 ETA가 없으므로 영상 길이 필터가 없음을 별도로 설명한다.
- core 33개 테스트, debug APK 빌드, lint 오류 0개·기존 경고 3개 통과. 실제 좌우 배치와 설명 가독성은 사용자 화면 검수 대상이다.

### 추천 카드와 선택 상태·홈 복귀

- 추천 영상을 썸네일, 제목, 게시자, 재생시간 배지가 있는 카드로 교체했다. 공식 YouTube 이미지 서버의 16:9 썸네일을 비동기로 읽고 메모리에만 캐시한다. 네트워크 오류 시 재생 아이콘을 유지하며 카드 선택은 가능하다.
- 확인·안전 조건 충족 후 플레이어만 미리 준비하고 자동으로 재생하지 않는다. 카드 선택 시 같은 WebView의 공식 IFrame API로 영상을 전환·재생 요청한다. 준비 전 선택은 마지막 선택을 보관했다가 준비 후 실행한다. 외부 링크도 선택한 영상으로 갱신한다. 실제 플랫폼에서 재생이 차단되면 플레이어의 직접 재생 안내를 유지한다.
- 설정 스위치는 테두리 있는 트랙과 밝은 손잡이, 켜짐/꺼짐 텍스트를 제공한다. 시간/목표 잔량 토글은 기존 형태를 유지하고 슬라이딩 선택 배경·선택 체크·굵은 글자로 상태를 구분한다.
- 설정에 진입하면 조작 패널의 톱니바퀴가 ‘← 홈’으로 바뀐다. Android 뒤로 가기도 설정에서 홈으로 돌아간다.
- core 33개 통과, APK 빌드 성공, lint 오류 0개·기존 경고 3개. JS 구문과 모의 IFrame 테스트로 사전 로딩 중 재생 없음, 직접 선택 재생, 잘못된 ID 거부, 준비 전 마지막 선택 우선, 링크 갱신을 확인했다. 두 썸네일 URL은 HTTP 200을 확인했다. 실제 기기의 카드 탭 재생·음성과 시각 배치는 별도 확인 대상이다.

### 설정 전환과 다이얼 조작 피드백

- 차량 연결 설정의 모의 충전·개발용 진단 전환은 해당 카드만 갱신한다. 높이 변화와 항목 표시/숨김을 260ms 전환으로 연결하고 화면 전체 재생성을 피한다.
- 설정 선택 메뉴는 둥근 어두운 패널, 선택 체크, 닫기 버튼을 가진 맞춤 Dialog로 교체했다. 긴 목록은 스크롤하며 시스템 애니메이션 비활성화를 따른다.
- 다이얼은 작은 중앙 영역을 제외한 내부까지 터치를 받는다. 조작 중 게이지 두께는 9dp에서 14dp, 손잡이 반지름은 13dp에서 18dp로 부드럽게 커지고 손을 떼거나 취소하면 복귀한다.
- core 테스트 결과 33개 통과, debug APK 빌드 성공, lint 오류 0개·기존 경고 3개. 실제 터치 감각과 애니메이션 시각 검수는 사용자 확인이 필요하다.
- Netflix 공식 안내의 앱/지원 브라우저 재생과 달리 Pleos 내 임베드 지원은 확인하지 못했다. 현재 에뮬레이터의 Netflix HTTPS 링크 처리기는 org.chromium.webview_shell이다. 이는 실제 Netflix 로그인·재생 지원 확인을 의미하지 않는다.

### Netflix 연결·글자 크기·언어 설정

- 홈 영상 목록 아래에 Netflix 외부 연결 카드를 추가했다. 사용자 선택 시 Netflix Android 앱으로 먼저 HTTPS 링크를 요청하고 처리 앱이 없거나 접근이 제한되면 일반 HTTPS 링크로 연다. 열기 직전에 기존 충전·안전 상태와 남은 시간 조건을 재확인한다. 자체 YouTube 재생은 일시정지한다. Netflix는 임베드/미리 로딩/남은 시간 추천 대상이 아니며 외부 재생을 앱에서 제어하지 못한다. 로그인·멤버십·기기 지원 조건을 카드에 명시했다.
- 현재 배터리 퍼센트는 26sp에서 48sp로 확대하고 ‘배터리’ 라벨은 기존 크기를 유지한다. 상단 해/달 밝기 전환 버튼은 제거하고 설정의 화면 밝기 항목은 유지한다.
- 설정 → 화면 및 배치에서 글자 크기 85/100/115/130%와 한국어/English를 선택할 수 있다. 기기 전체 설정을 바꾸지 않고 앱 설정으로 저장하며, Activity의 로컬 Configuration에 적용한다. 변경 시 설정 화면과 진행 중 알림 체크포인트를 복원한다. 글자 크기는 시스템 폰트 배율에 곱해 적용하며 다이얼 숫자는 영역에 맞춰 최대 폭을 제한한다.
- 메뉴·상태·권한 안내·진단·영상 카드·YouTube 호스트 안내를 한국어/영어 리소스로 분리했다. 콘텐츠 제목과 외부 서비스 자체 UI는 서비스 언어를 따른다. 번들 언어 분할을 끄므로 두 언어를 오프라인에서 전환할 수 있다. 앱 내부 WebView 안내에는 글자 배율을 적용하며 YouTube iframe 자체 제어 글자 크기는 보장하지 않는다.
- 두 언어 247개 문자열 키와 포맷 인자 일치를 검사했고 양쪽 YouTube HTML의 JavaScript 구문 검사를 통과했다. 실제 Netflix 로그인·재생과 큰 글자/영어의 화면 배치 및 설정 전환은 별도 기기 확인 대상이다.
- 최종 검증: core 33개 통과, assembleDebug 성공, lint 오류 0개·기존 버전 안내 경고 3개. emulator-5554의 현재 운전자 user 10을 재확인해 APK 설치 및 MainActivity 실행(Status: ok)을 완료했다. 실행 직후 AndroidRuntime 오류는 관찰되지 않았다. 실제 화면 확인 완료를 의미하지 않는다.

### 조작 패널 가운데 정렬

- 제목 양옆의 공간을 동일하게 배치하여 설정/홈 버튼 너비와 무관하게 패널 중심에 제목을 맞췄다. 모의 충전 표시와 배터리 텍스트도 다이얼·알림 설명·버튼과 같은 중앙선을 사용한다. 설정/홈 조작은 왼쪽에 유지한다.
- 진행 중 알림의 ‘다시 설정’을 ‘초기화’로 변경했다. 기존 세션 초기화 동작은 유지한다.
- core 테스트, debug 빌드, lint 통과(오류 0개·기존 경고 3개). 에뮬레이터 user 10에 설치 및 실행 완료. 실제 화면의 정렬 검수는 별도이다.

### 음성 완료 안내·단색 테마·패널 이동

- Gleo 직접 발화 API가 아니라 Pleos TextToSpeech 3.3.1의 ON_DEVICE 모드를 연결했다. 공식 문서의 Gleo callback은 명령에 대한 응답이므로 타이머가 끝난 뒤 임의 callback을 보내지 않는다. TTS_SERVICE 권한과 SDK 전이 의존성용 Pleos security Maven 그룹을 추가했으며 기존 SDK/Gradle 버전은 유지했다.
- 시간 모드 완료 시 정확한 elapsedRealtime 마감 시각을 기준으로 한 번만 합성을 요청한다. 완료 체크포인트를 먼저 저장한다. 전경·차량 안전 상태가 확인된 경우에만 동작하며 화면 이탈·상태 유실·오디오 포커스 상실 시 중지한다. 초기화/재생 오류와 15초 제한을 처리하고 오디오 포커스와 SDK 자원을 해제한다. 외부 앱, 화면 꺼짐, 앱 종료 중 안내는 지원하지 않으며 늦은 복귀 알림을 재생하지 않는다. 목표 잔량 알림은 이번 음성 안내 범위에 포함하지 않는다.
- 설정에 음성 안내 스위치와 미리 듣기를 추가했다. 앱 언어에 따라 ko-KR/en-US를 지정한다. 실제 기기 서비스·음량·음성 데이터에 따른 출력 검수는 별도이다.
- 배경 선택에 단색 블랙/화이트를 추가했다. 단색은 그라데이션·광원·애니메이션을 그리지 않으며 카드·텍스트·게이지·토글·선택 메뉴 대비를 함께 변경한다.
- 설정의 ‘← 홈’을 제거하고 화면 하단 중앙에 플로팅 ‘확인’을 추가했다. 마지막 설정 아래에 버튼을 피할 스크롤 여백을 둔다. Android 뒤로 가기는 유지한다.
- 넓은 화면 조작 패널 맨 아래에 반대 방향 화살표 버튼을 추가했다. 설정의 패널 위치 선택과 같은 movePanel 함수를 호출하여 위치 저장·스크롤 보존·320ms 이동 효과를 처리한다. 좁은 화면에서는 기존 세로 배치를 유지하고 방향 버튼은 표시하지 않는다. 시스템 애니메이션 비활성화 시 즉시 이동한다.
- 타이머 종료 직전/정각, 중복 완료, 비활성·잔량 모드, 백그라운드·늦은 복귀 음성 억제 및 단색 팔레트 테스트를 추가했다.
- 선택 모달의 푸른 고정색을 제거하고 어두운 반투명 배경(화이트 테마는 밝은 반투명), 중립 선택 배경·테두리·체크를 사용한다. 주변 dim은 25%로 조정했다.
- 최종 검증: core 37개 통과, debug APK 빌드 성공, lint 오류 0개·경고 32개(기존 버전 안내 3개, TTS가 가져온 KTX 사용 권고 24개, JNA x86_64 네이티브 라이브러리 16KB 정렬 경고 3개, 제거한 홈 버튼의 미사용 번역 2개). SDK 전이 라이브러리를 임의로 업그레이드하지 않았다. 16KB 페이지 기기 배포는 별도 검증/SDK 대응이 필요하다.
- emulator-5554 user 10에 설치 및 MainActivity 실행(Status: ok)을 완료했다. 새 PID의 실행 직후 AndroidRuntime 오류는 관찰되지 않았다. 음성 미리 듣기의 실제 소리는 사용자 확인을 요청했으며 재생 검증 완료로 간주하지 않는다.

### 하단 공통 버튼과 음성 엔진 오류 확인

- 패널 하단 버튼 생성은 buildPanelActionButton, 실행 분기는 performPanelAction으로 통합했다. 홈에서는 기존 movePanel로 좌우 이동하며 설정에서는 확인 후 홈으로 이동한다. 별도의 플로팅 확인 버튼과 이를 위한 설정 하단 여백을 제거했다. 좁은 화면에서도 설정 확인 버튼은 표시한다.
- 사용자 미리 듣기에서 TTS_SERVICE 권한과 SDK 초기화는 정상이나 ON_DEVICE_ENGINE_ERROR가 확인됐다. 서비스 로그의 근본 오류는 `Failed to load MetaSpace byte pair encoder`다. ‘SDK start callback’은 음성이 실제 출력됐다는 증거가 아니므로 로그 표현을 수정했다. 해당 엔진 오류는 별도 사용자 안내로 구분한다.
- 사용자 요청으로 기존 AVD 데이터를 유지하며 스냅샷 없이 cold boot했다. sys.boot_completed=1 및 현재 운전자 10을 확인하고 새 APK를 설치·실행했다. 재시작 후 미리 듣기 결과는 사용자에게 재확인을 요청했다. 음성 문제 해결 완료로 간주하지 않는다.
- core 37개 테스트, debug 빌드 및 lint 완료(오류 0개·경고 32개). 공통 버튼의 실제 화면 확인과 재시작 후 음성 출력은 별도 검증 대상이다.

### 패널 간격과 SDK 재검토

- 패널 헤더 아래 12dp, 모의 충전 표시 아래 12dp, 배터리 아래 20dp, 모드 토글 아래 20dp 여백을 적용했다. 빈 알림 부제와 빈 상태 라벨은 GONE 처리해 다이얼 아래의 불필요한 간격을 줄였다.
- SDK 사용을 공식 initialization-and-release, set-locale, start-and-stop 문서와 재대조했다. ON_DEVICE 생성 → 초기화 성공 → 이벤트 등록 → ko-KR/en-US 설정 → speak(text, true) 순서 및 TTS_SERVICE 권한은 확인됐다. cold boot 후에도 서비스의 MetaSpace byte pair encoder 로딩 오류가 반복됐다. 현재 근거로 호출 순서보다 내부 모델/엔진 문제가 유력하며 성공적인 음성 출력은 여전히 미확인이다. 서버 방식은 별도의 Pleos 프로젝트 등록을 필요로 한다.

### 설정 적용 문구와 단색 움직임 잠금

- 설정 하단 공통 버튼의 표시를 ‘설정 적용’/‘Apply settings’로 변경했다. 타이머 확인 버튼의 문구는 유지한다.
- 단색 블랙·화이트에서는 배경 움직임 스위치를 꺼진 비활성 상태로 표시하고 잠금 이유를 안내한다. 기존 움직임 선호값은 보존해 그라데이션으로 돌아오면 복원한다. 다른 설정 스위치는 기본 enabled=true로 기존 동작을 유지한다.

### Pleos 프로젝트 생성 및 서버 음성 검증

- 사용자 승인으로 Pleos My Project에 프로젝트명/개발사명 모두 ‘빈틈의실’인 프로젝트를 생성했다. TextToSpeech 관리 화면은 ‘준비 중(Coming Soon)’이고 사용 신청/활성화 동작은 표시되지 않았다.
- SDK 최소 진단 Instrumentation을 추가하고 앱 UI·오디오 포커스·커스텀 AudioAttributes 없이 테스트했다. ON_DEVICE 한국어와 영어 모두 initialized=true, synthesis:ON_DEVICE_ENGINE_ERROR였다.
- 개발용 SERVER 연결은 앱 비공개 files/pleos-tts.json에 자격 증명이 있을 때만 활성화한다. 값은 소스·APK 상수·Git에 넣지 않았으며 이 에뮬레이터 user 10의 앱 전용 파일에만 전달했다. release 빌드에서는 해당 파일을 읽지 않는다.
- SERVER 최소 진단: initialized=true, 서버 onConnected 후 합성 요청, startCallback=true, 최종 outcome=synthesis:PERMISSION_DENIED. 서비스 원문은 ‘Unsupported endpoint or you do not have permission to use that endpoint’다. 초기화 또는 start 콜백을 실제 음성 출력 성공으로 간주하지 않는다.
- TextToSpeech 서비스/프로젝트 권한 또는 지원 엔드포인트 상태를 Pleos 측에 확인해야 한다. 앱은 권한 거부를 별도 안내한다. 음성 기능은 아직 미완료이며 사용 가능하다고 보고하지 않는다. 지원 요청에 자격 증명 또는 전체 인증 로그를 첨부하지 않는다.
- 서버 등록은 공식 app-registration의 registerApp(Client ID, Client Secret, listener) 및 onConnected 이후 speak 순서를 사용한다. 요청 제한은 등록 시간을 포함해 30초이며 화면 이탈 시 자원을 해제한다.
