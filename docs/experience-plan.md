# 빈틈의실 경험 확장 실행 계획

2026년 11월 8일 계획. **남은 시간과 취향에 맞는 활동을 고르고, 제때 마무리하도록 돕는 앱**으로 발전시킨다. 영상 목록을 많이 보여주는 것보다 ‘지금 할 만한 3개’와 선택 이유, 종료 시점을 제공하는 것이 중심이다. 현재 코드는 모의 데이터 프로토타입이며 아래 기능은 구현 계획이다.

## 제품 흐름

`차량 상태 확인 → 사용할 시간 선택 → 차 안 / 차 밖 선택 → 추천 3개 → 활동 진행 → 마무리 안내 → 선택적 피드백`

차량 화면은 활동을 고르고 세션을 시작하는 곳이다. 차 밖 이동은 휴대폰이 담당한다. 차량의 위치를 사용자의 현재 위치로 간주하지 않는다. 충전 상태와 사용자 활동은 독립적으로 유지해, 영상 재생 실패 때문에 충전 상태 표시까지 멈추지 않게 한다.

첫 화면에서는 목표 SOC와 최신 충전 상태, 사용자가 선택한 대기시간을 구분한다. SDK가 신뢰할 수 있는 충전 예상시간을 실제 제공하는지 확인하기 전에는 사용자가 고른 시간을 사용한다. ‘선택한 20분’을 ‘충전 완료까지 20분’으로 바꾸지 않는다.

## 시간에 따라 제공할 활동

아래 구간은 초기 제품 가설이다. 실제 후보의 준비·활동·이동·마무리 시간을 계산한 뒤 남는 것만 제시한다. 데이터가 부족하면 3개를 억지로 채우지 않는다.

| 사용자가 정한 시간 | 차 안 후보 | 차 밖 후보 | 추천에서 피할 것 |
| --- | --- | --- | --- |
| 5분 이하 | 1~2분 눈 쉬기, 짧은 호흡 안내, 한 줄 생각 정리 | 출발 추천 없이 주변 장소 둘러보기 | 새 긴 영상, 주문 대기, 외출 |
| 6~15분 | 자체 퀴즈, 3~8분 자체 콘텐츠, 길이가 확인된 짧은 영상 후보 | 실제 왕복·체류·여유가 맞는 경우만 이후 검토 | 직선거리만 보고 가까운 매장 추천 |
| 16~30분 | 짧은 영상, 10분 휴식, 가족용 음성 퀴즈 | 검증된 짧은 왕복 산책, 포장 간식 후보 | 영업 중·주문 대기시간을 추정으로 확정 |
| 31~60분 | 15~25분 콘텐츠, 복합 휴식 루틴 | 공원 왕복, 카페·간식 한 곳 | 여러 매장을 묶는 과도한 코스 |
| 60분 초과 | 사용자가 원할 때만 긴 콘텐츠, 중간 점검 시점 제공 | 이동·대기 불확실성이 작은 단일 목적지 | 긴 에피소드 완주나 충전 완료시간 보장 |

자체 콘텐츠부터 준비한다: 3분 눈 쉬기, 5분 생각 정리, 8분 쉬운 퀴즈. 길이·저작권·중단 동작을 직접 통제할 수 있어 공급자 연결 실패에도 첫 흐름을 유지할 수 있다. 의학적 효과를 주장하지 않는 일반 휴식 안내로 작성한다.

## 미디어와 웹 연동 결정

| 방법 | 계획 | 구현 전 확인 |
| --- | --- | --- |
| 자체 콘텐츠 | 1차 필수. 로컬 텍스트·타이머·짧은 퀴즈 | 중단·복구와 안전 제한 전환 |
| YouTube 후보 검색 | 서버의 소수 큐레이션 목록에서 시작. 원본 길이와 삽입 가능 여부 확인 | API 키, 쿼터, 메타데이터 갱신·삭제 정책 |
| YouTube 내부 재생 | 공식 IFrame Player를 이용하는 조건부 기능 | Pleos WebView 실제 재생, 식별·광고·쿠키·네트워크·주행 제한 |
| 외부 앱이나 공식 웹 링크 | 설치된 앱 또는 허용된 브라우저가 있을 때 사용자 선택으로 열기 | Intent 처리 가능 여부, 복귀, 영상이 실제 중단되는지 |
| Netflix | 자체 검색·재생 API와 플레이어를 전제로 개발하지 않음 | 제3자 공개 재생 API와 Pleos 지원이 확인되지 않음. 정상 지원 앱/브라우저의 공식 공유 링크만 별도 검토 |
| 임의 사이트를 여는 범용 브라우저 | 초기 범위 제외 | 운전자 조작 제한, 인증·팝업·다운로드·재생 상태 제어 부담 |

YouTube 원본 영상 길이는 전체 체류시간이 아니다. 광고·버퍼링·로그인 시간을 포함해 ‘시간 안에 끝남’을 보장하지 않는다. 영상 길이를 자르거나 광고를 가리거나 오디오만 추출하는 방식은 사용하지 않는다. 시간 종료 시 안내와 사용자 종료 선택을 제공하고, 안전 제한 시에는 플레이어를 실제 중지하는 경로를 검증한다. 외부 앱 실행으로 우리 앱이 그 앱의 재생을 중단할 수 있다고 가정하지 않는다.

YouTube 영상 ID·제목·재생 이력·시청시간으로 사용자 취향 점수를 만들지 않는 것을 초기 설계 방침으로 둔다. 개인화는 사용자가 직접 입력한 활동 선호와 자체 활동 피드백을 사용한다. 미디어 정책과 새 쿼터는 [YouTube 정책](https://developers.google.com/youtube/terms/developer-policies), [IFrame API](https://developers.google.com/youtube/iframe_api_reference), [쿼터 안내](https://developers.google.com/youtube/data/determine_quota_cost)를 기준으로 검토한다. 브라우저 지원은 해당 서비스와 기기에서 별도로 확인한다. [Netflix 브라우저 요구사항](https://help.netflix.com/en/node/30081)

## 주변 간식과 산책

장소 검색과 실제 보행 경로를 별도로 요청한다. 기본 공급자 후보는 Kakao Local과 Kakao 도보 경로를 함께 사용하는 방식이며 TMAP은 대체 어댑터 후보다. 제공사 앱의 실제 권한·쿼터·요금 설정을 확인한 뒤 선택한다. 가입·결제·유료 전환은 이 계획에 포함하지 않는다.

1. 사용자가 주변 검색을 누를 때 충전소 위치와 선택 카테고리만 요청한다.
2. 카페·편의점·공원 후보를 조회하고 공급자·마지막 조회 시각을 보인다.
3. 출발지→목적지, 목적지→충전소를 각각 보행 경로로 계산한다. 왕복 시간을 직선거리나 한쪽 경로의 단순 2배로 대체하지 않는다.
4. 산책은 검증된 왕복 경로부터 시작한다. 생성 AI가 공원 안의 길이나 보행 가능 구간을 만들어내지 않게 한다. 순환 코스는 실제 경유점과 각 구간의 경로가 확보된 뒤 추가한다.
5. 영업시간이나 대기시간을 제공받지 못하면 ‘확인 필요’로 표시한다. Kakao Local 검색 결과만으로 ‘영업 중’ 배지를 만들지 않는다.
6. 이동 시간과 체류·대기·복귀 여유가 예산을 넘으면 추천에서 제외한다. 경로 실패·위치 거절·시간 불명은 출발 가능한 후보가 아니다.

차 안 활동의 기본 마무리 여유는 2분, 외출의 기본 복귀 여유는 5분을 초기 가정으로 둔다. 외출 예시: 30분 예산에 가는 길 6분 + 체류 8분 + 오는 길 7분 + 여유 5분 = 26분이다. 20분 예산이면 같은 후보는 탈락한다. 광고·매장 대기·횡단보도 지연 등 미확정 요소가 커지면 여유를 늘리거나 후보를 보류한다.

충전 추정 범위를 나중에 제공받더라도 하한값을 확정 마감으로 취급하지 않는다. 사용자가 직접 정한 시간·확정 출발시각을 상한으로 두고 추정치의 신뢰도와 변경을 별도로 표시한다. 예산이 줄었을 때 이미 출발한 사람에게 새 코스를 조용히 바꾸지 않고 휴대폰에서 복귀 판단을 안내해야 한다.

**차 밖 출발의 출시 조건:** 실제 보행 경로, 휴대폰 인계, 휴대폰의 화면 잠금·백그라운드·절전 상태에서 확인한 귀환 알림이 모두 필요하다. QR을 열었다는 사실만으로 알림 전달이 검증된 것은 아니다. 이 조건 전에는 장소·경로 ‘미리보기’만 제공한다. 수동 귀환 타이머와 실시간 충전 상태 알림은 다른 기능이며, 차량 Suspend나 연결 단절 후에도 충전 감시가 된다고 표시하지 않는다.

Kakao Local의 장소 정보와 지도/도보의 반환·표시 조건을 확인한다. 제공자 응답을 영구 수집하지 않고, 경로 공유·캐시·타사 지도 표시의 허용 범위는 실제 사용 조합에 맞춰 검토한다. [Kakao Local](https://developers.kakao.com/docs/latest/ko/local/dev-guide) · [Kakao 도보 경로](https://developers.kakao.com/docs/latest/ko/kakaomap/rest-api#walking)

## 개인화의 단계

첫 사용에는 활동 종류(보기·쉬기·걷기·간식), 기본 이용 장소(차 안·차 밖), 조용한 활동 선호만 선택적으로 받는다. 공용 차량이므로 ‘이번만 이용’과 개인 프로필을 분리한다. 생년월일·차량번호·원시 위치 이력은 취향 학습에 필요하지 않다.

첫 단계는 시간 구간별 취향 점수와 명시적 피드백을 로컬에 저장한다. 노출, 선택, 시작, 완료, 만족을 구분한다. 충전 목표 도달이나 네트워크 오류 때문에 중단한 행동은 싫어요로 해석하지 않는다. ‘시간이 길었어요’는 길이 적합성에, ‘이 활동이 싫어요’는 활동 종류에 반영한다.

강화학습 계열 확장은 상황별 밴딧을 후보로 둔다. 충분한 동의 기반 로그와 비교 검증 후, 안전 필터를 통과한 차량 내 자체 활동의 마지막 카드에서만 소규모로 탐색한다. 안전·시간·주행 제한·제공자 정책은 학습 모델이 완화할 수 없다. 시청시간과 클릭 수가 아니라 만족도·마무리 성공·반복 알림 감소를 평가한다. 자세한 규칙과 이벤트는 [추천 설계](recommendation-design.md)에 정리한다.

## UI와 API를 먼저 확정할 항목

화면 계약은 [UI 명세](ui-spec.md), 공급자 연결과 로컬 경계는 [API 설계](api-spec.md), HTTP 계약은 [OpenAPI](api/openapi.json)를 따른다. OpenAPI는 아직 서버가 구현되지 않은 제안 계약이다.

- 추천 카드: 활동명, 소요시간의 근거, 준비·왕복·여유, 선택 이유, 제공자, 실행 가능 상태.
- 진행 화면: 시간과 충전 상태를 분리하고 중단 원인·감시 불가를 명확히 표시.
- 상태 분리: 목표 도달, 타이머 종료, 충전 중단, 안전 제한, 미디어 실패, 외출 인계 실패.
- 제공자 대체: 콘텐츠 API 장애는 자체 활동으로, 보행 경로 장애는 차 안 활동 또는 주변 검색으로 전환.

## 실패해도 유지할 시연과 검증

1. 20분 선택 → 자체 활동 3개 → 하나 시작 → 목표 SOC 이벤트 → 중복 없이 안내.
2. 8분으로 변경 → 긴 후보 제외 → 짧은 휴식 선택. 광고가 있는 영상은 완주 보장으로 표시하지 않음.
3. 30분 외출 미리보기 → 왕복·체류·여유 표시 → 휴대폰 검증이 없으면 출발 기능 제한.
4. 같은 자체 활동에 명시적 피드백을 남김 → 다음 같은 시간 구간에서 순위 변경. 이 시연은 규칙 기반 개인화이며 RL 학습 성과로 표현하지 않음.
5. API 실패·위치 거절·오래된 차량 상태·주행 제한에서 적절한 대체 또는 중단 확인.

우선 측정할 지표는 추천 선택까지 걸린 시간, 제약을 위반한 후보 수, 유효 목표 이벤트의 누락·중복, 명시적 만족 피드백, 사용자가 확인한 마무리 성공이다. 실제 차 밖 복귀는 사용자의 확인이나 동의한 휴대폰 위치 증거 없이 완료로 기록하지 않는다.
