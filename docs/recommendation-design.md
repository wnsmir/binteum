# 빈틈의실 추천·개인화 실행 설계

## 현재 구현 — 2026-11-10

이 절은 `codex/charge-aware-dashboard`의 현재 추천·기록 동작이다. 아래의 2026-11-08 확장 설계에 있던 수동 타이머 중심 흐름과 고급 점수식·외출·밴딧은 현재 구현으로 간주하지 않는다.

**시간의 출처를 분리한다.** AAOS의 유효한 잔여 충전시간은 차량 목표와 앱 목표가 일치할 때만 사용한다. ETA가 없거나 더 낮은 앱 목표를 선택했다면, 최근 관측에서 2분 이상·SOC 2%p 이상 증가가 확인된 뒤 최근 속도 기준 근사치를 구할 수 있다. 오래된 데이터·중단·SOC 하락·표본 공백에서 추정 이력을 초기화한다. 실제 차량 한도보다 높은 앱 목표까지 충전된다고 추정하지 않는다. 예측한 시각이 지났다는 이유로 목표 도달을 만들어내지 않는다.

사용자가 정한 출발 시각은 독립적인 마감이다. 추천은 OEM ETA 또는 근사치와 출발까지 시간 중 이른 쪽을 사용한다. 근사치에는 20% 짧은 추천 예산을 **출발 제약과 비교하기 전에** 적용하며, 이후 콘텐츠 길이와 마무리 120초를 비교한다. 이 보정은 실제 충전 종료나 콘텐츠 완주를 보장하지 않는다. 충전 ETA도 출발 시각도 없으면 시간에 맞는 추천은 보류한다.

**추천과 직접 선택은 분리한다.** 대시보드는 시간 조건에 맞는 영상·자체 활동을 최대 3개 제안한다. 하단 영상·활동 탭은 ETA 미확인이나 시간 부족에도 직접 열 수 있다. 이 자유 선택은 충전·안전 상태 확인을 대신하지 않는다. 충전 중단·주행 제한·안전 미확인·휴면·앱 이탈의 차단 경계는 유지한다.

### 현재 기록과 순위 규칙

- SQLite에 명시적 선택마다 로컬 ID·시각·활동 종류·직접/추천 경로·**원래 남은 충전시간 및 출처**·SOC·선택 목표·시연 여부를 저장한다. 출발까지 시간을 충전시간으로 대체하지 않는다.
- 자체 활동은 같은 선택 ID에 진행 시간·명시적 완료/중단·좋아요/별로예요를 갱신한다. 중복 저장은 선택 수를 늘리지 않는다. 중단 자체는 불호 평가가 아니다.
- 영상은 일반적인 ‘영상 선택’만 기록한다. 개별 YouTube/Netflix ID·제목·검색어·시청시간·시청 완료 등 제공자 재생 이력을 저장하거나 선호도 특징으로 사용하지 않는다. 외부 앱 열림을 재생 성공이나 완료로 간주하지 않는다.
- 충전 잔여시간 구간은 **미확인 / 5분 미만 / 5~15분 미만 / 15~30분 미만 / 30분 이상**이며, 마무리 시간을 빼기 전 원래 충전 예상값이다. SOC 구간은 **미확인 / 40% 미만 / 40~80% 미만 / 80% 이상**이다. 미확인 ETA를 0분이나 짧은 대기로 학습하지 않는다.
- 같은 시간 구간의 선택 빈도를 사용하고 SOC 구간도 같으면 더 높은 가중치를 준다. 자체 활동의 명시적 완료 평가는 좋아요 +2, 별로예요 -4로 보정한다. 선호도가 높아도 대시보드의 시간 적합성 조건을 우회하지 않는다.
- 시연 기록은 보존하되 실제 순위·평가 프로필에 반영하지 않는다. 최근 4,000개의 실제/시연 포함 조회 캐시에서 시연을 제외해 순위를 계산하며, 이전 SQLite 기록은 사용자가 삭제할 때까지 남는다.
- 사용자는 설정에서 기록을 보고 모두 삭제할 수 있다. ‘기록으로 추천 순서 맞추기’를 꺼도 선택 기록은 계속 저장하며, 순위 보정만 중단한다. 데이터는 기기에만 보관하고 기존 백업 제외 규칙을 적용한다.

현재 알고리즘은 설명 가능한 빈도·평가 규칙이다. 강화학습 모델, 맥락 밴딧, 서버 학습, 위치·외출 경로 추천은 구현하지 않았다. 최종 통합 검사 결과와 실제 기기 데이터·기록 정합성 검수는 확인 중이다.

## 이전 확장 설계 — 2026-11-08

이하 내용은 **2026-11-08 당시 작성한 후속 개발 계획**이다. 당시 모의 차량 데이터와 고정 시간 예산을 출발점으로 작성했으며, 아래 계획 전체가 현재 작동한다는 뜻이 아니다. 이후 구현된 범위는 이 문서 상단을 우선한다. 외출 안내·휴대폰 알림·학습 실험 등은 기존 [제품 기획](product-plan.md)과 함께 후속 설계로 보존한다.

추천의 목적은 “대기시간 동안 만족스러운 활동을 하고 제시간에 마무리하기”다. 시청시간·클릭 수·체류시간을 최대화하지 않는다. 시간·안전·실행 가능성·외출 경로 조건은 선호 점수보다 먼저 적용한다.

## 1. 개발 순서와 통과 조건

| 단계 | 구현할 것 | 다음 단계로 넘어갈 조건 |
| --- | --- | --- |
| P0 | 실제 안전 신호, 세션 상태, 시간 입력, 카운트다운, 종료·중단·복구 | 제한·불명 상태 차단, 실제 시간 경과와 재시작 처리 검증 |
| P1 | 직접 선호 3문항, 자체 콘텐츠, 규칙 기반 최대 3개 추천, 로컬 초기화 | 시간에 맞는 실행·종료, 명시적 평가와 중복 방지 검증 |
| P2 | 짧은 영상·한정 웹 읽기 | 제공자 정책, 검색·표시·실행·중단 수단, 차량 제한 전환을 각각 확인 |
| P3 | 산책·간식, 휴대폰 전달과 복귀 계획 | 실제 도보 경로와 실기기 휴대폰 알림·백그라운드·연결 해제 검증 |
| P4 | 자체 콘텐츠 평가에 따른 로컬 선호 보정 | 노출·시작·종료·만족도 로그 정합성과 삭제·옵트아웃 검증 |
| P5 | 선택적 맥락 밴딧 실험 | 충분한 허용 데이터, 오프라인 검토, 별도 참여 동의, 중단 기준 확보 |

P2의 미확인 제공자는 실행 가능한 추천으로 표시하지 않는다. P3는 모든 검증을 통과하기 전 **미리보기 전용**이다. 개인화와 밴딧은 공모전 MVP의 필수 의존성이 아니다.

## 2. 서로 다른 세 가지 시간

| 값 | 의미 | 변경 규칙 |
| --- | --- | --- |
| 수동 선택 시간 | 사용자가 이번 세션에 쓰겠다고 정한 시간 | 최초 시작 시각과 함께 종료 시각을 고정한다. 조회할 때마다 현재 시각을 더하지 않는다. |
| 사용자 마감 `hardDepartureAt` | 사용자가 차로 돌아와 출발 준비를 마쳐야 하는 절대시각 | 수동 시간과 따로 저장한다. 자동 추정이나 학습으로 연장하지 않는다. |
| 충전 예상 구간 | 관측을 바탕으로 계산한 가장 이른 예상 시각과 늦은 예상 시각 | 관측 시각·유효기간·방법·검증 상태를 함께 저장한다. 미검증·오래된 추정은 계산에서 제외한다. |

충전 예상 구간의 이른 시각도 실제 종료 시각의 보장 하한이 아니다. 목표 잔량 도달 알림, 충전 중단, 사용자 마감, 활동 타이머 종료는 계속 다른 사건으로 처리한다.

계획 종료 시각은 존재하는 수동 종료 시각과 사용자 마감 중 이른 시각으로 잡는다. 검증되고 최신인 충전 예상 구간이 있으면 그 이른 시각도 보수적인 추천 한도로 적용한다. 사용할 수 있는 시간 정보가 하나도 없으면 시간을 입력받으며 임의로 20분을 채우지 않는다.

```text
수동 종료 시각 = 최초 세션 시작 시각 + 선택 시간
계획 종료 시각 = 사용 가능한 종료 시각들 중 가장 이른 시각
활동 예산 = max(0, 계획 종료까지 남은 초 - 모드별 여유)
후보 비용 = 준비 + 나가는 도보 + 활동 + 돌아오는 도보
시간 적합 조건 = 후보 비용 <= 활동 예산
동일한 조건 = 후보 비용 + 모드별 여유 <= 계획 종료까지 남은 초
```

모드별 여유의 초기값은 **차 안 마무리 120초(2분), 외출 복귀 300초(5분)**다. 외출에 120초와 300초를 중복해서 빼지 않는다. 사용자가 조절할 수 있지만 학습 모델이 줄이지 않는다. 후보 비용에는 보수적으로 잡은 계획값을 사용하며 이것도 실제 완료 보장을 뜻하지 않는다. 간식의 활동시간에는 대기·수령·섭취를 포함한다.

같은 기기 부팅 안의 카운트다운은 단조 시계를 사용한다. 사용자 마감은 절대시각으로 보존하고, 시계 변경·재시작·복구 시 두 값을 다시 확인한다. 예상 충전시간이 길어져도 진행 중 타이머를 자동 연장하지 않는다. 짧아지면 적합성을 다시 계산하고 마무리하도록 안내한다.

### 초 단위 시간 구간

아래 구간은 **모드별 여유를 뺀 뒤**의 활동 예산이다. [경험 계획의 시간 구간](experience-plan.md#시간에-따라-제공할-활동)은 사용자가 선택한 전체 시간을 기준으로 하므로 두 구간의 기준이 다르다. 구간은 추천 특징과 화면 설명에만 사용하며 초 단위 적합성 검사를 대체하지 않는다.

| 구간 | 정확한 범위 | 초기 제안 |
| --- | --- | --- |
| 2분 미만 | 0초 이상, 120초 미만 | 0초면 종료 안내. 양수면 그 안에 끝나는 자체 휴식 |
| 2~5분 미만 | 120초 이상, 300초 미만 | 짧은 자체 활동·길이가 확인된 영상·한정 읽기 |
| 5~10분 미만 | 300초 이상, 600초 미만 | 짧은 영상·웹·휴식 |
| 10~20분 미만 | 600초 이상, 1,200초 미만 | 차량 내 활동 다양화 |
| 20~40분 미만 | 1,200초 이상, 2,400초 미만 | 외출 검증 이후 왕복 활동 검토 |
| 40분 이상 | 2,400초 이상 | 긴 대기도 나눠 제안, 자동 연속 재생 없음 |

아래 산술표는 **차 안 활동에 여유 120초를 적용한 예시**다.

| 입력 예시 | 계산된 활동 예산 | 판단 |
| --- | --- | --- |
| 수동 20분, 더 이른 종료 조건 없음 | 1,200 - 120 = **1,080초** | 12분 영상 + 준비 30초 = 750초 적합 |
| 같은 세션에서 7분 경과 | 780 - 120 = **660초** | 앞의 750초 영상은 부적합. 5분 읽기 + 준비 30초는 적합 |
| 수동 20분, 사용자 마감은 12분 뒤, 유효 추정은 15~25분 | 720 - 120 = **600초** | 사용자 마감 우선. 9분 영상 + 준비 30초 = 570초 적합, 여유 점수는 낮음 |
| 수동 20분, 검증된 최신 추정은 8~16분 | 480 - 120 = **360초** | 5분 영상 + 준비 30초 = 330초 적합. 8분을 보장하지 않음 |
| 수동 20분, 충전 추정이 오래되거나 미검증 | 1,200 - 120 = **1,080초** | 추정 무효 표시. 차량 내 수동 활동 기준이며 외출 허용 근거가 아님 |
| 수동 2분 | 120 - 120 = **0초** | 새 활동 없이 마무리 안내 |

외출이 검증된 이후에는 활동비용에 **복귀 여유 300초**를 더한 총비용으로 전체 남은 시간과 비교한다. 남은 시간이 20분(1,200초)이면 외출 활동 예산은 1,200 - 300 = 900초다.

| 외출 미리보기 사례 | 활동비용 | 여유를 포함한 총비용 | 전체 남은 시간 20분에서의 시간 판단 |
| --- | --- | --- | --- |
| 왕복 도보 8분 + 산책 5분 | 780초 | 780 + 300 = **1,080초(18분)** | 시간 조건 통과 |
| 왕복 도보 8분 + 대기 4분 + 수령·섭취 5분 | 1,020초 | 1,020 + 300 = **1,320초(22분)** | 시간 초과로 제외 |

이는 현재 미리보기 사례이며, 시간 조건 통과만으로 외출을 허용하지 않는다. 실제 도보 경로·장소 정보·휴대폰 알림 조건을 모두 확인한 뒤에만 활성화한다.

영상은 확인된 길이와 준비 여유를 사용한다. 길이가 없는 웹은 “5분만 읽기”처럼 사용자가 끝낼 수 있는 세션으로 제안하며 “5분이면 다 읽음”이라고 표시하지 않는다.

## 3. 점수 계산 전에 제외할 후보

다음 조건 중 하나라도 통과하지 못하면 높은 선호 점수로 복구할 수 없다.

1. **안전:** 최신 실제 안전 신호가 상호작용을 허용해야 한다. 제한·불명·휴면에서는 상세 활동을 차단한다. 사용자 확인 버튼이나 수동 시간 모드로 우회하지 않는다.
2. **세션:** 현재 활동 가능한 세션이어야 한다. 목표 도달·충전 중단·마감·종료 상태에서 새 활동을 추천하지 않는다. 충전 중단 후 사용자가 수동 시간 모드를 명시 선택해도 안전 확인은 필요하다.
3. **사용자 조건:** 차 안에 머물기, 활동 제외, 최대 걷기 시간, 제공자 차단 등 직접 설정을 지킨다.
4. **시간:** 준비·이동·활동·복귀를 포함한 비용이 실제 남은 예산 이하여야 한다.
5. **실행과 제공자:** 해당 기기에서 실행·중단·제한 전환이 가능하고 제공자 사용 조건이 확인되어야 한다.
6. **외출 경로:** 실제 도보 왕복 경로, 출입 가능 여부, 갱신 상태를 확인한다. 차량 위치를 사람 위치로, 직선거리나 차량 경로를 도보 경로로 취급하지 않는다.
7. **휴대폰 복귀 알림:** 실기기 페어링·테스트 알림 확인·로컬 복귀 타이머·백그라운드와 연결 해제 처리가 검증되어야 한다.
8. **장소:** 영업·대기·재고 정보의 불확실성을 구분한다. 사용자가 음식 제외조건을 선택했다면 미확인 재료를 적합하다고 표시하지 않는다.

## 4. 첫 이용 질문과 카드 구성

질문은 모두 건너뛸 수 있다. 질문에 답하지 않아도 차량 내 자체 활동 추천은 사용할 수 있다.

| 질문 | 선택 방식 | 건너뛰기 |
| --- | --- | --- |
| 기다릴 때 하고 싶은 것은? | 짧은 영상·웹 읽기·조용히 쉬기·산책·간식/카페 중 최대 2개 | 모두 중립 |
| 관심 있는 주제는? | 과학/기술·여행/풍경·요리·문화/취미·가벼운 재미 중 최대 3개 | 주제 선호 없음 |
| 어느 정도 걸어도 괜찮은가요? | 차 안·왕복 10분·왕복 20분 | 차 안 기본값 |

산책 선호를 고른 것은 외출 알림 검증을 통과했다는 뜻이 아니다. 소리 사용 여부와 이번에 하고 싶은 활동은 세션 안에서 바꿀 수 있다.

초기 순위는 재현 가능한 규칙으로 계산한다. 아래 가중치와 특징값은 검증할 제품 가정이다.

```text
점수 = 35P + 20C + 20T + 20R + 5N       (각 특징은 0~1)
여유 초 = 활동 예산 - 후보 비용
T = clamp(여유 초 / max(60, min(300, 활동 예산 / 3)), 0, 1)
```

| 특징 | 의미 |
| --- | --- |
| P | 직접 선택한 선호와 허용된 자체 콘텐츠 평가의 적합도. 모르면 0.5, 명시적 제외는 점수 전에 차단 |
| C | 이번 세션에서 직접 고른 모드·소리·활동 목적과의 적합도. 감정·건강 상태를 추론하지 않음 |
| T | 계획에 남는 여유. 대기시간을 빈틈없이 채울수록 높은 점수가 되는 방식은 사용하지 않음 |
| R | 실행·중단 수단과 시간·정보의 확인 정도. 필수 확인이 안 된 후보는 먼저 제외 |
| N | 자체 콘텐츠 반복 완화. 새 자체 항목 1, 최근 항목 0. 외부 콘텐츠는 0.5 고정 |

가상의 특징값이 자체 휴식 `(0.6, 1, 1, 1, 1)`이면 86점, 영상 `(0.9, 0.7, 1, 0.8, 0.5)`이면 84점, 웹 `(0.7, 0.8, 1, 0.7, 0.5)`이면 77점이다. 이는 점수 계산 예시이며 실제 데이터에서 산출한 성과가 아니다. P·C·R의 세부 매핑은 샘플 후보와 사용자 검토 후 버전이 있는 규칙표로 고정한다.

첫 카드는 최고 적합 후보, 두 번째는 다른 활동 종류, 세 번째는 부담이 낮은 자체 활동 또는 남은 적합 후보를 우선한다. 같은 종류는 최대 2개, 동일 항목은 한 번만 표시한다. 적합 후보가 1~2개면 그 수만 표시하고 0개면 이유와 다음 행동을 알려준다. 미리보기는 활성 카드와 분리하며 활성 추천 노출로 집계하지 않는다.

카드에는 계획 시간, 마무리 여유, 간단한 추천 이유를 표시한다. 순위는 사용자 변경·유효성 변경·새 추천 요청에서 갱신하고 매초 재정렬하지 않는다.

## 5. 사건과 학습을 구분

| 사건 | 뜻 | 곧바로 뜻하지 않는 것 |
| --- | --- | --- |
| 추천 생성 | 후보를 계산함 | 사용자가 봄 |
| 카드 노출 | 실제 표시 조건을 충족함 | 선택·만족 |
| 선택 | 카드를 누름 | 활동 시작·긍정 평가 |
| 전달 열림 | 링크 또는 QR 목적지를 엶 | 재생·페어링·알림 성공 |
| 활동 시작 | 자체 실행 또는 사용자 확인 | 외부 페이지가 열렸다는 추정 |
| 타이머 종료 | 정한 시간이 경과함 | 활동 완료·복귀 |
| 활동 완료 | 자체 관측 또는 명시적 사용자 확인 | 만족·외부 영상 시청 완료 |
| 활동 중단 | 원인과 함께 실행을 멈춤 | 취향에 안 맞음 |
| 명시적 평가 | 사용자가 자체 활동을 평가함 | 외부 제공자 시청 이력 |
| 복귀 확인 | 사용자 확인 또는 별도 검증 수단으로 확인함 | 차량 위치·타이머·앱 종료만으로 확인 |

노출 조건의 시작안은 카드 면적 50% 이상이 2초 이상 보이는 경우다. 이는 검증할 계측 정의이며 사람의 주의나 이해를 증명하지 않는다.

중단 사유는 목표 도달, 충전 중단, 사용자 마감, 주행 제한, 휴면, 차에서 내림, 계획 변경, 자체 콘텐츠에 대한 명시적 불호, 네트워크 오류, 제공자 오류로 나눈다. **외출·목표 도달·마감·기술 오류를 취향의 부정 사례로 학습하지 않는다.** “별로였어요”에도 내용 불호와 시간·기능 문제를 구분한다.

### 로컬 개인화

직접 선호와 명시적 제외가 우선이다. 초기에는 결정적 맥락 규칙만 사용하고, 학습을 켠 사용자의 자체 콘텐츠 평가가 쌓이면 보조 점수로 반영한다.

자체 콘텐츠의 명시적 좋음·내용 불호를 각각 긍정·부정 카운트에 1씩 더하는 시작안을 사용한다. 보정값은 `(2 + 긍정) / (4 + 긍정 + 부정)`로 둔다. 사전값 2/2는 초기 제품 가정이다. 맥락별 데이터가 적으면 더 넓은 자체 활동 종류 또는 중립값으로 돌아가며 작은 차이를 확실한 취향이라고 설명하지 않는다.

활동 시도별 평가는 하나만 집계한다. 수정 시 이전 카운트를 되돌린 뒤 새 평가를 반영한다. 반복 이벤트는 멱등 처리한다. 카드의 시작 유효기간과 활동 후 피드백 유효기간은 분리한다. 초기 제안은 자체 활동 시작 후 24시간까지 평가를 받는 것이며, 세션이 끝났다는 이유만으로 정상 피드백을 버리지 않는다. 삭제·초기화 시 평가 권한도 폐기한다.

**YouTube ID·제목·시청·완료 로그를 개인화 프로필 학습에 사용하지 않는다.** 사용자가 설정에서 직접 고른 선호와 자체 콘텐츠 평가를 중심으로 한다. 외부 콘텐츠를 열었다는 이유로 주제·취향을 자동 갱신하지 않는다. 제공자 표시·검색·재생 조건은 별도 확인 대상이다.

## 6. 차량·외출·휴대폰 화면 흐름

차량 안에서는 시간과 목표를 고르고 최대 3개 카드 중 하나를 시작한다. 목표 도달이나 예산 축소 시 마무리 흐름으로 이동한다. 점수 변경만으로 실행 중 활동을 교체하지 않는다.

외출 기능은 “도보 왕복 + 대기/활동 + 복귀 여유 5분”을 초기 기준으로 보여준다. 실기기 검증 전에는 기능 설명과 계산 예시만 제공한다. 외출 시작 버튼을 활성화하지 않는다.

```text
연결 안 됨 → 링크 열림 → 페어링 완료
→ 테스트 알림 요청 → 실제 휴대폰에서 수신 확인
→ 휴대폰 복귀 타이머 설정 완료
```

QR 열림은 알림 성공이 아니다. 연결 저하 상태는 별도로 표시한다. 인터넷이나 차량 연결이 끊겨도 휴대폰 로컬 타이머가 작동하는지 실기기로 검증하고, 차량 충전 상태의 실시간 관측이 끊겼다면 그 한계를 알린다. 알림 권한, 앱 백그라운드·종료, 잠금, 네트워크 단절을 포함한 검증 전에는 외출 가능 상태로 전환하지 않는다.

## 7. 내부 컴포넌트 데이터 계약

아래는 내부 DTO 제안이며 HTTP 주소나 서버 도입 결정을 뜻하지 않는다.

| DTO | 필수 내용 |
| --- | --- |
| `RecommendationContext` | 로컬 세션·요청 ID, 현재 시각/단조 시각, 세션 상태, 수동 종료·사용자 마감·충전 예상 구간, 여유 시간, 안전 상태와 관측 시각, 모드, 직접 선호, 허용된 자체 집계, 실행 기능·정책 버전, 휴대폰 확인 상태 |
| `CandidatePlan` | 세션 내 후보 키, 종류, 제공자 종류, 정확/한정 세션/추정/미확인 시간 유형, 준비·활동·왕복 비용, 경로 검증과 시각, 요구 조건, 학습 허용 범위, 활성/미리보기/제외와 사유 |
| `RecommendationResult` | `READY / NOOP / NEED_TIME_INPUT / BLOCKED_SAFETY`, 예산 초, 활성 카드 0~3개, 분리된 미리보기, 카드 만료 시각, 이유·점수, 필요한 다음 행동 |
| `ActivityEvent` | 이벤트·세션·활동 시도 ID, 추천/평가 토큰, 사건 종류와 시각, 관측 출처·자기 보고 여부, 자체 콘텐츠 키, 중단 사유·평가, 학습 허용 검사 결과 |
| `PreferenceUpdateResult` | `UPDATED / NOOP`, 반영 또는 무변경 이유, 실제 변경 시만 증가하는 프로필 버전 |

외부 ID·제목·URL은 표시와 실행에 필요한 범위에서 다루며 개인화 이벤트에서 제거한다. 외부 자료의 저장·보존 여부는 제공자 정책 검토 후 결정한다. 안전 상태를 사용자가 직접 확인했다고 입력하는 값으로 대체하지 않는다.

| 조건 | 해야 할 일 |
| --- | --- |
| 안전 제한·불명·휴면 | 상세 추천 차단, 학습 갱신 없음 |
| 목표 도달·충전 중단·종료 | 새 추천 중지, 해당 상태 확인·마무리 |
| 시간 정보 없음 | 시간 선택 한 가지를 요청 |
| 예산 0초 또는 사용자 마감 도달 | 마무리만 안내 |
| 외출 또는 제공자 조건 미충족 | 미리보기 또는 차량 내 자체 대안 |
| 적합 후보 없음 | 빈 결과와 이유, 무리하게 카드 수를 채우지 않음 |
| 중복 이벤트·만료/폐기된 평가 토큰 | 선호 변경 없음 |
| 무응답·타이머 종료·시스템/외출 중단·외부 시청 사건 | 선호 변경 없음 |

## 8. 맥락 밴딧은 뒤의 선택적 실험

처음부터 완전한 강화학습을 도입하지 않는다. 직접 선호와 규칙, 자체 평가 집계가 제품 가치를 만드는지 먼저 확인한다.

밴딧의 초기 데이터 점검안은 허용된 자체 콘텐츠 노출 1,000건, 명시적 평가 200건, 주요 맥락에서 적어도 2개 선택지의 관측이다. 이 숫자는 표본 충분성이나 우월성의 보장이 아니며 충족만으로 출시하지 않는다. 이벤트 정확성·맥락별 분포·시간순 검증·평가 결측·표시 위치 편향을 확인하고, 먼저 화면에 반영하지 않는 그림자 실행을 한다.

결정적 추천 로그에는 선택되지 않은 대안의 결과가 없다는 제약이 있다. 관측될 확률이 0인 후보의 효과를 그 로그만으로 평가했다고 주장하지 않는다. 부분 관측 로그와 오프라인 재생 평가의 조건은 [Li 등의 원 논문](https://arxiv.org/abs/1003.5956)을 참고한다.

이후 별도 참여 동의 세션의 최대 5%에서 **안전 조건을 통과한 차량 내 자체 콘텐츠의 세 번째 카드만** 탐색하는 시작안을 검토한다. 앞의 두 카드는 결정적 추천을 유지한다. 선택 가능한 후보 집합, 세 번째 자리의 조건부 선택 확률, 정책 버전을 기록한다. 이 범위의 평가 결과를 전체 카드나 외출 추천 성능으로 확대하지 않는다.

보상은 명시적 만족도 좋음 1·보통 0.5·나쁨 0을 시작안으로 둔다. 무응답은 결측이며 0점으로 바꾸지 않는다. 동일한 평가 요청 방식, 분석 대상, 결측 처리와 응답률을 실험 전에 정한다. 응답자 만족도만 높아진 것을 전체 사용자 개선으로 표현하지 않는다.

사용자 마감·복귀 준수는 만족도와 교환하지 않는 별도 제한 지표다. 안전·시간·마무리 여유·경로·휴대폰 알림·제공자 정책·음식 제외조건을 탐색 대상으로 삼지 않는다. 필터 위반, 잘못된 선택 확률, 제한 상태 노출, 만족도 악화 신호, 실행·알림 장애가 나오면 규칙 추천으로 되돌린다.

## 9. 개인정보와 평가 기준

계정 없이 로컬 프로필로 시작한다. 건강·감정·민감한 특성, 외부 시청 습관, 정밀 이동 이력을 추론하지 않는다. 경로에 필요한 현재 위치와 외부 표시 데이터를 선호 이력으로 옮기지 않는다. 원시 자체 활동 이벤트의 보존 시작안은 30일 또는 최근 500개 중 먼저 닿는 한도이며, 집계값도 초기화 대상이다. 실제 보존 정책과 사용자 안내는 구현 시 확정한다.

학습 끄기는 갱신을 멈추고 직접 선호만 사용한다. 학습 초기화는 집계·자체 이력·대기 중 평가 권한을 삭제한다. 전체 선호 초기화는 사용자가 선택한 제외조건까지 삭제하므로 별도로 확인한다. 향후 서버로 실험 데이터를 보내려면 로컬 추천 사용과 분리된 동의를 받는다.

주요 지표는 명시적 만족도와 응답률, 사용자 마감 준수, 확인된 복귀와 확인 불가 비율이다. 보조 지표는 활동을 고르는 시간, 활동 변경, 자체 활동 재이용, 제공자 실행 실패다. 타이머 종료를 복귀, 클릭을 만족, 영상 완료를 선호로 대체하지 않는다.

검증에는 다음 사례를 포함한다.

- 시간 구간 경계 119/120, 299/300, 599/600, 1,199/1,200, 2,399/2,400초와 0초.
- 세션 경과 후 예산 감소, 더 이른 사용자 마감, 오래된 추정 제외, 시계 변경과 재시작.
- 목표 도달·충전 중단·안전 불명·주행 제한에서 새 추천 차단.
- 외출 경로·실기기 알림 중 하나라도 없으면 외출 비활성, QR 열림만으로 활성화되지 않음.
- 생성·노출·선택·시작·완료·중단의 분리와 반복 이벤트 무변경.
- 외출·시간·시스템 사유 중단은 선호 무변경, 유효한 종료 후 자체 피드백은 반영.
- 학습 끄기·초기화·평가 수정과 외부 제공자 데이터가 프로필에 남지 않음.

제공자 사용 방식, 충전 추정 오차, 도보·장소 데이터 공급원, 휴대폰 전달 방식은 아직 결정·검증할 항목이다. 위의 임계값·가중치·실험 비율은 모두 구현 및 사용자 검증 전의 제안값이다.
