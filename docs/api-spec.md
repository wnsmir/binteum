# 빈틈의실 API와 데이터 경계

2026년 11월 8일 제안 명세. 현재 저장소에는 HTTP 서버나 실제 공급자 연결이 없다. [OpenAPI 계약](api/openapi.json)은 이후 구현할 BFF의 입출력을 정의하며 실제 배포 주소나 API 키가 아니다.

## 최소 구조

```text
Android UI → SessionCoordinator → 로컬 추천 엔진 → 로컬 선호 저장소
                         ↓
             VehicleDataSource / SafetyGateway / Timer / TTS

외부 후보가 필요할 때만 Android → BFF → 콘텐츠·장소·도보 공급자
휴대폰 인계·충전 알림 동기화는 별도 후속 구성
```

첫 시연은 서버 없이 자체 콘텐츠·수동 시간·모의 또는 검증된 차량 데이터로 동작해야 한다. BFF는 공급자 키와 요청량을 관리하는 경계다. 사용자 취향의 로컬 랭킹을 만들기 위해 처음부터 계정·대규모 이벤트 서버·벡터 DB·LLM을 도입하지 않는다.

## 앱 내부 인터페이스 초안

아래 이름은 빈틈의실이 정의할 내부 컴포넌트다. Pleos SDK의 공식 패키지나 메서드라고 해석하지 않는다. 실제 SDK 서명은 공식 샘플과 설치 아티팩트에서 대조한다.

| 컴포넌트 | 입력과 출력 | 책임 |
| --- | --- | --- |
| VehicleDataSource | 최신 VehicleSnapshot 스트림 | SOC·충전·관측시각·지원 여부. 현재 인터페이스 확장 검토 |
| SafetyGateway | SafetySnapshot 스트림 | 플랫폼 주행 제한과 신호 신선도. UNKNOWN은 허용 아님 |
| SessionCoordinator | 시작·목표 변경·중단·복구 이벤트 → SessionState | 차량 감시와 활동 상태 조정, 중복 알림 방지 |
| BudgetCalculator | 선택시간·출발시각·선택적 충전 추정 → Budget | 초 단위 잔여 예산, 근거·불확실성·수정 이력 |
| EligibilityFilter | 후보·예산·안전·기능 상태 → 적격 후보와 탈락 이유 | 하드 제약. 학습 엔진이 우회 불가 |
| RecommendationEngine | 적격 후보·로컬 선호 → 최대3개 카드 | 개인화·다양성·이유. 차단된 후보 재진입 금지 |
| PreferenceStore | 직접 선호·자체 활동 피드백 | 로컬 저장·프로필 분리·삭제. 원시 위치와 YouTube 이력 제외 |
| MediaLauncher | 공급자별 실행 요청 → 실행 상태 | 공식 플레이어/허용 Intent, 실제 중지 가능 여부 |

필수 시간 타입은 구분한다: `selectedDurationSec`(사용자 선택), `departureAt`(사용자 출발시각), `chargeEstimate`(관측 시각·범위·출처가 있는 추정), `activityRemainingSec`(앱 타이머). 실제 지속시간은 단조 시계로 계산하고 표시·서버 만료시각은 UTC ISO 8601로 교환한다. 휴면·프로세스 재시작 후 시계 차이와 최신 차량 상태를 다시 확인한다.

## BFF 계약

| 경로 | 역할 | 초기 활용 |
| --- | --- | --- |
| GET /v1/activities | 직접 작성한 활동 카탈로그 | 앱 번들로 시작해 같은 스키마 유지 가능 |
| POST /v1/media/youtube/candidates | 큐레이션 후보의 원본 길이·삽입 가능 상태 조회 | 공급자 검증 후 연결, 개인 시청기록 요청 없음 |
| POST /v1/places/search | 사용자 요청 시 주변 장소 검색 | 위치 거절 시 사용 안 함, 영업 상태 UNKNOWN 허용 |
| POST /v1/outings/preview | 왕복 보행·체류·여유를 포함한 계획 검토 | 경로 실패는 출발 가능으로 응답하지 않음 |

OpenAPI의 `feasible`은 입력한 시간 예산과 확보한 경로에 따른 계산 결과다. 안전한 보행·매장 영업·휴대폰 알림·충전 상태 전달을 보증하는 필드가 아니다. UI의 ‘차 밖 시작’ 허용은 로컬 안전·알림 준비 게이트를 추가로 통과해야 한다.

추천 엔진과 이벤트 저장은 초기에는 앱 안에서 실행한다. 따라서 HTTP `/train`이나 모델 업데이트 API를 만들지 않는다. 이후 서버 학습이 필요하면 동의·삭제·보존기간·실험 정책과 인증 계약을 먼저 추가한다.

## 공급자 어댑터

| 어댑터 | 원천 데이터 | 처리 원칙 |
| --- | --- | --- |
| OwnContentAdapter | 자체 활동의 길이·종류·본문 | 오프라인 기본 후보, 수정 이력 관리 |
| YouTubeAdapter | 공식 Data API와 IFrame Player | 검색 남발 대신 큐레이션, 원본 속성·허용 재생 경로, 개인 취향용 파생점수 제외 |
| KakaoPlaceAdapter | Local 키워드·카테고리 검색 | 경도/위도 순서, 공급자 ID·출처, 없는 영업시간 생성 금지 |
| KakaoWalkAdapter | 공식 도보 경로 | 실제 권한·요금 확인 후 사용. 왕복 각각 요청·시간은 초로 정규화 |
| TmapWalkAdapter | 공식 보행 경로 | 카카오 사용 조건을 충족하지 못할 때 대체 검토. 좌표·지도 표시 정책 별도 확인 |

제공자 명세와 자체 API는 분리한다. 호출자가 임의 URL을 넘겨 서버가 가져오는 범용 프록시는 만들지 않는다. 서버에서 제공자와 호스트를 고정하고 입력 반경·개수·좌표·요청량을 제한한다. 클라이언트가 보낸 ‘검증됨’ 값만으로 출발 가능 상태를 만들지 않는다.

## 인증과 개인정보

서버 도입 시 제공자 비밀키는 서버의 비밀 저장소에만 둔다. APK·Git·QR에는 넣지 않는다. OpenAPI의 Bearer는 앱이 사용할 단기 세션 자격증명에 대한 제안이다. 발급·회전·폐기와 속도 제한은 구현 착수 전에 확정해야 하며, APK 안의 고정 공유 키를 인증으로 쓰지 않는다.

주변 검색에는 그 요청에 필요한 위치와 카테고리만 전달하고 원시 좌표를 추천 이력 DB나 일반 로그에 보관하지 않는다. 앱의 선호는 프로필별 로컬 저장을 기본으로 하며, 사용자가 개인화 중단·초기화를 할 수 있어야 한다. 수집·보존기간과 동의 문구는 실제 배포 구성에 맞춰 확정한다.

휴대폰 인계 토큰은 후속 설계다. 이 기능을 만들 때에는 짧은 만료, 1회 사용, 세션별 범위, 취소·교체, QR의 민감정보 최소화가 필요하다. 정적 QR에 차량 식별자·위치 이력·장기 토큰을 넣지 않는다. 공식 경로 URL 공유가 공급자 정책상 허용되는지도 확인한다.

## 실패와 검증

- 입력 형식과 범위 오류는 400, 인증 실패는 401, 사용 불가능한 권한은 403, 제공자 제한은 429, 일시적 장애는 503으로 구분한다. 사용자가 이해할 수 있는 오류 코드와 재시도 가능 여부를 반환한다.
- 장소가 없음은 정상적인 빈 배열이다. API 장애를 빈 배열로 숨기지 않는다.
- 왕복 중 한 구간만 성공하거나 경로·시간을 확인하지 못하면 적합성을 확정하지 않는다. 실패 사유와 확보한 부분을 구분한다.
- 공급자별 동시 요청과 시간 제한을 두고, 시간 초과 시 차 안 자체 활동으로 복귀한다. 상태를 바꾸는 작업은 중복 처리 방지 키를 후속 계약에 포함한다.
- 좌표 순서, 초/분 단위, 0개 후보, 보행 경로 없음, 왕복 비대칭, 429, 미디어 비공개·삽입 불가, 오래된 결과를 계약 테스트 대상으로 둔다.
- 모의 응답과 실제 응답은 데이터의 출처 필드로 구분하고, 릴리스에서 모의 값을 실시간 장소·영상으로 표시하지 않는다.

기능 확정 전 계정 키 발급·권한·결제·쿼터·메타데이터 보존·지도 표시 조건을 확인한다. 이 문서의 엔드포인트가 존재한다는 이유로 제3자 API 사용 승인을 받았다고 주장하지 않는다.
