# 빈틈의실 UI 명세 초안

2026년 11월 8일. 가로형 차량 화면과 휴대폰 인계를 위한 구현 계획이다. 디자인 검토용 시뮬레이션은 실차 화면·재생·지도 서비스가 아니다. 플랫폼의 크기·터치·주행 제한 기준은 Pleos 가이드와 실제 기기에서 최종 확인한다.

현재 구현 화면의 테마·아이콘·게이지·반응형 배치 변경은 [UI 고도화 기록](ui-refinement.md)을 기준으로 확인한다. 아래 내용에는 아직 구현하지 않은 휴대폰 인계·차 밖 흐름도 포함되어 있다.

## 정보 구조

화면 상단에는 목표 SOC, 충전 상태의 최신성, 사용자가 선택한 시간, 감시 가능 여부를 유지한다. 홈의 주요 행동은 ‘차 안’과 ‘차 밖’이다. 추천 화면에서는 한 번에 최대 3개의 선택지를 보여준다. 처음부터 검색창·무한 스크롤·콘텐츠 서비스 목록을 펼치지 않는다.

시간 문구는 출처에 따라 다르게 쓴다.

| 값 | 표시 예 | 금지할 오해 |
| --- | --- | --- |
| 사용자 선택 | 이번에 쓸 시간 20분 | 충전 완료까지 20분 |
| 활동 타이머 | 활동 6분 남음 | 차량 충전 잔여시간 |
| 추정 충전 시간 | 충전 예상 18~25분 · 갱신 30초 전 | 18분 뒤 반드시 완료 |
| 확정 출발 시각 | 15시에는 출발 | 알고리즘이 조용히 연장 |
| 데이터 없음 | 충전 상태 확인 불가 | 캐시된 잔량을 현재값처럼 표시 |

## 화면 목록과 동작

| 화면 | 필수 요소 | 주 행동 | 예외 |
| --- | --- | --- | --- |
| S0 시작·프로필 | 이번만 이용, 개인 프로필, 선택적 선호 3문항 | 건너뛰고 시작 | 미선택도 기본 추천 가능 |
| S1 대기 설정 | 최신 SOC, 목표, 10·20·30분/직접 입력, 출발 시각 선택 | 추천 보기 | 안전 불명 시 상세 조작 제한 |
| S2 추천 | 차 안/차 밖, 카드 최대3개, 추천 이유, 시간 구성 | 하나 선택, 다른 제안 | 유효 후보가 적으면 적게 표시 |
| S3 상세 | 콘텐츠 제공자 또는 실제 왕복 경로, 준비·활동·여유 | 활동 시작 / 휴대폰으로 미리보기 | 공급자 불가·위치 거절·귀환 알림 미검증 |
| S4 진행 | 남은 활동시간, 목표와 현재SOC, 즉시 종료, 활동 변경 | 마무리 / 중단 | 충전 중단과 목표 도달을 구분 |
| S5 마무리 | 종료 원인, 선택적 만족 피드백과 이유 | 완료, 다음에 다시 | 미디어 종료 이벤트를 복귀 완료로 취급하지 않음 |
| S6 선호·개인정보 | 학습 켜기/끄기, 시간 구간별 선호 수정, 기록 삭제 | 저장 또는 초기화 | 다른 차량 이용자에게 이전 프로필 노출 방지 |
| P1 휴대폰 인계 | 공식 경로 링크, 반환시각, 알림 상태, 충전 감시 범위 | 인계 확인 / 알림 시험 | QR 열기만으로 출발 준비 완료로 표시하지 않음 |

## 추천 카드 계약

카드에는 제목보다 먼저 사용자가 판단할 수 있는 시간이 보여야 한다. 미디어는 원본 재생 길이, 외출은 왕복·체류·여유를 포함한 계획시간이다. 두 시간을 같은 ‘소요시간’만으로 묶지 않는다.

```text
[이번에 쓸 시간 30분]   [차 안] [차 밖]

충전소 주변 공원 왕복 · 가상 예시
왕복 13분 + 머무르기 8분 + 여유 5분 = 계획 26분
이유: 걷기를 선호하고, 설정한 30분 안에 들어와요
영업/출입: 확인 필요   경로: 공급자 조회 1분 전
[자세히 보기]          [휴대폰 인계 필요]
```

실제 장소가 아니면 화면 전체에 ‘가상 예시’ 표시를 유지한다. 가상 매장을 실제 영업 중인 장소처럼 보이게 하지 않는다. 실제 데이터에 없는 평점·가격·혼잡도·영업 상태를 채우지 않는다.

YouTube 카드 예시는 ‘원본 영상 8분 · 광고/로딩 별도’이다. 개인화 근거에는 앱에 직접 입력한 ‘차 안에서 보기 선호’를 쓸 수 있지만, 시청 이력에서 학습한 것처럼 표시하지 않는다. 서비스의 로고·썸네일·출처 표시는 공급자 가이드를 따른다.

## 레이아웃 원칙

- 주 화면은 큰 제목과 세 개 이하의 주요 후보, 분명한 주 행동 하나를 중심으로 구성한다.
- 시간·충전 상태는 미디어 위를 가리는 오버레이로 만들지 않는다. 플레이어 밖의 독립 영역에 둔다.
- 브랜드를 가리거나 공식 플레이어 조작·광고를 덮지 않는다.
- 활동 도중 추천 목록을 자동 교체하지 않는다. 예산 변화는 안내하고 사용자가 재선택하게 한다.
- 가로 화면에서는 상태와 활동을 나누고, 좁은 화면에서는 상태→모드→추천 순으로 쌓는다.
- 앱 설정과 피드백에 운전 중 접근할 수 있게 만드는 우회 경로를 두지 않는다.

## 상태 전이와 우선순위

`SETUP → RECOMMENDING → DETAIL → ACTIVE → WRAP_UP → FINISHED`

배터리 관측 상태와 활동 상태는 별개다. 안전 제한 상태는 모든 상세 화면에 우선한다. 차 밖 활동은 `PREVIEW → HANDOFF_PENDING → HANDOFF_VERIFIED → ACTIVE_OUTSIDE`로 분리하며, 검증되지 않은 기능은 PREVIEW 이후로 전이하지 않는다.

| 사건 | 사용자 문구 | 처리 |
| --- | --- | --- |
| 목표 SOC 도달 | 설정한 80%에 도달했어요 | 한 번 안내, 세션의 마무리 요청 |
| 타이머 종료 | 정한 시간이 끝났어요 | 활동 종료 선택 |
| 목표 전 충전 중단 | 충전 상태가 바뀌었어요. 확인해 주세요 | 완료로 기록하지 않음 |
| 둘이 동시 발생 | 정한 시간이 끝났고 목표 잔량에도 도달했어요 | 한 번의 결합 안내 |
| 차량 값 지연 | 충전 상태를 확인할 수 없어요 | 최신값처럼 표시하지 않음, 수동 타이머와 구분 |
| 주행 제한·안전 불명 | 안전한 정차 상태에서 이용해 주세요 | 상세 화면 차단, 내부 재생 중지 |
| 영상 오류 | 이 영상은 여기서 재생할 수 없어요 | 자체 활동 선택으로 복귀 |
| 외부 앱 실행 | 외부 앱에서 재생해요 | 외부 앱 재생 제어·완료를 보장하지 않음 |
| 도보 경로 오류 | 걸어서 다녀올 시간을 확인할 수 없어요 | 출발 추천 제외 |
| 휴대폰 인계 실패 | 휴대폰에서 귀환 알림을 확인해 주세요 | 출발 준비 완료로 표시하지 않음 |

목표 도달이 모든 미디어를 강제로 중지해야 한다는 요구와, 안전 제한에 따라 반드시 중지해야 하는 요구를 구분한다. 정상적인 시간 종료는 사용자가 알아볼 수 있게 안내하고 마무리 선택을 받는다. 안전 제한에서는 사용자의 추가 조작 없이 제한 정책을 적용한다. 외부 서비스에서 이 동작이 불가능하면 해당 실행 경로를 출시하지 않는다.

## 피드백

종료 후 ‘좋았어요 / 아쉬웠어요 / 건너뛰기’를 선택적으로 제공한다. 아쉬움의 이유는 ‘활동이 별로’, ‘너무 길었음’, ‘준비·이동이 번거로움’, ‘앱 오류’ 정도로 구분한다. 충전 완료나 수동 종료만으로 아쉬움에 자동 표시하지 않는다. 질문은 활동 종료 뒤 한 번이며 주행 중 표시하지 않는다.

세션 만족과 미디어 서비스 평가를 구분한다. YouTube의 자체 평가 UI를 흉내 내거나 자체 좋아요를 YouTube 좋아요처럼 전달하지 않는다. 개인화 저장 대상은 직접 제공한 앱 선호와 자체 활동 평가로 제한한다.

## 검수 시나리오

1. 8분·20분·40분에서 추천이 시간 예산에 맞게 바뀐다.
2. 차 밖에서 보행 경로 또는 휴대폰 알림이 미확인이면 미리보기만 가능하다.
3. 후보가 0개일 때 사유와 자체 휴식으로 돌아갈 행동이 보인다.
4. 광고와 로딩이 발생해도 확정 종료시간처럼 보이지 않는다.
5. 안전 제한 전환은 영상이 보이는 상태와 WebView 내부 포커스 상태에서도 작동한다.
6. 폰 화면 잠금·네트워크 단절·차량 Suspend에서 실제 제공 범위를 과장하지 않는다.
7. 개인 선호를 끄거나 삭제한 뒤 다음 추천에 이전 기록이 반영되지 않는다.
8. 게스트와 개인 프로필 전환에서 이전 사용자의 활동이 노출되지 않는다.

이 명세와 별개로 실제 Pleos 기기의 글자 크기·터치 영역·주야간 대비·접근성·화면 비율을 검수한다. 개발 중 편의상 쓰는 시연 버튼은 사용자 화면에서 제거한다.
