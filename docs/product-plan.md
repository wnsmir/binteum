# 빈틈의실 제품 기획

빈틈의실은 전기차 충전 중 사용자가 정한 시간에 맞춰 짧은 휴식과 정리 활동을 제안하고, 목표 배터리 잔량 도달 또는 활동 종료를 알려주는 Pleos Connect 앱이다. 첫 버전은 **차량 안에서 대기하는 경험**을 완결하는 데 집중한다.

이 문서는 공동 개발의 MVP 기준이다. 목표 기능과 코드 구현, 실제 기기 검증 상태를 구분하며 [구현·검증 기록](implementation-status.md)을 함께 확인한다.

2026년 11월 8일 확장 요청을 반영한 [경험 확장 실행 계획](experience-plan.md), [UI 명세](ui-spec.md), [API 설계](api-spec.md), [추천 설계](recommendation-design.md)를 함께 읽는다. 이 문서는 차량 내 기본 세션의 완료 기준으로 유지하며, 콘텐츠·개인화·외출의 최신 구현 순서와 조건은 확장 계획을 따른다. 새 명세 작성은 기능 구현 완료를 뜻하지 않는다.

## 문제와 대상 사용자

첫 대상은 공용 충전소에서 충전하는 동안 차 안에 머무르는 Pleos Connect 지원 전기차 사용자다. 해결하려는 문제는 다음과 같다.

- 충전 상태를 반복해서 확인하느라 쉬는 활동에 집중하기 어렵다.
- 사용할 수 있는 시간에 맞춰 무엇을 할지, 언제 마무리할지 결정하기 어렵다.
- 활동 중 충전이 중단되거나 목표 잔량에 도달해도 이를 놓칠 수 있다.

불편의 빈도와 크기는 사용자 인터뷰로 검증한다. 초기 핵심 가치는 **시간 선택 → 짧은 활동 → 차량 상태에 따른 마무리**가 하나의 세션으로 이어지는 것이다.

## 제품 결정

1. 목표 잔량은 앱의 알림 기준이다. 차량의 충전 한도를 변경하거나 충전을 자동 종료하지 않는다.
2. 사용자가 고른 대기시간과 충전 완료 예상시간을 구분한다. 첫 버전은 정확한 충전 완료 시각을 예측하지 않는다.
3. 목표 잔량 도달, 충전 중단, 활동 타이머 종료를 다른 사건으로 처리한다.
4. 초기 버전은 사용자가 앱을 열어 세션을 시작한다. 충전 시작 시 자동 실행하거나 차량 전원 종료 후 계속 감시한다고 약속하지 않는다.
5. 차량 내 알림으로 범위를 정한다. 휴대폰 전달이 연결되지 않은 상태에서 차 밖 알림을 제공한다고 표시하지 않는다.

## 핵심 사용 흐름

1. **상태 확인:** 현재 잔량, 충전 상태, 마지막 갱신 시각, 사용할 알림 수단을 확인한다. 안전 상태가 허용될 때 상세 조작을 연다.
2. **목표와 시간 선택:** 알림을 받을 목표 잔량과 이번에 사용할 시간을 고른다. 현재 시간 선택지는 8분, 20분, 40분, 60분이며 직접 입력은 후속 기능이다.
3. **활동 선택:** 조용히 쉬기, 짧은 생각 정리 등 최대 3개의 자체 활동 중 하나를 선택한다.
4. **진행과 마무리:** 활동 남은 시간을 보여준다. 목표 잔량 도달, 타이머 종료, 충전 상태 변경이 발생하면 해당 원인을 구분해 안내한다. 사용자는 활동을 즉시 끝내거나 바꿀 수 있다.
5. **종료 확인:** 사용자가 활동 완료를 확인하면 평가를 선택할 수 있다. 시간 구간별 직접 선호와 자체 활동 평가를 로컬에 저장하며 학습을 끄거나 초기화할 수 있다.

예를 들어 15분을 선택하면 3분 생각 정리나 8분 조용히 쉬기를 제안할 수 있다. **활동 길이 + 마무리 여유 ≤ 사용자가 선택한 시간**인 항목만 추천한다. 기본 마무리 여유는 제품 가정인 2분이며 조절 가능하게 설계한다.

목표가 80%일 때에는 “설정한 80%에 도달했어요”라고 안내한다. 70%에서 충전이 멈췄다면 “충전 상태가 변경됐어요. 확인해 주세요”라고 안내한다. 두 경우를 모두 충전 완료라고 표현하지 않는다.

## MVP 범위

| 기능 | 목표 동작 | 구현 경계 |
| --- | --- | --- |
| 충전 세션 | 최신 차량 데이터와 안전 상태를 확인하고 시작·종료 | 초기에는 사용자가 직접 시작 |
| 목표 잔량 알림 | 설정한 잔량 이상에 도달하면 같은 세션에서 한 번 안내 | 충전량 제어 기능이 아님 |
| 시간 선택 | 정해진 시간 선택과 직접 입력 | 충전 잔여시간으로 표시하지 않음 |
| 짧은 활동 | 시간 예산에 맞는 자체 활동 최대 3개 제안 | 외부 콘텐츠·계정 연동 없이 시작 |
| 타이머와 종료 | 활동 종료·중단·변경, 목표 도달과 동시 종료 시 결합 안내 | 실제 카운트다운과 상태 저장 구현 필요 |
| 수동 시간 모드 | 안전 조건이 허용되고 배터리 데이터만 없을 때 타이머 사용 | 충전 감시가 꺼져 있음을 명확히 표시 |
| 오류와 복구 | 권한 거절, 미지원 기능, 지연, 연결 해제, 재시작을 구분 | 성공하지 않은 연결을 정상으로 표시하지 않음 |

실제 차량 연동은 `VehicleDataSource` 경계 안에서 구현한다. 필요한 SDK 서명과 권한, 지원 기능을 확인하고 최소 범위만 연결한다. Gleo는 연동 조건이 확인된 뒤 추가하는 음성 입력 수단이며, 기본 화면 흐름의 필수 의존성으로 두지 않는다.

Gleo 후보 동작은 목표 알림 설정, 시간에 맞는 활동 조회, 현재 세션 상태 조회다. 차량 데이터 관찰과 활동 실행은 앱이 담당하며, Gleo가 장시간 감시를 대신한다고 가정하지 않는다.

## 안전과 상태 처리

안전 조건 확인을 배터리 데이터 확인보다 먼저 수행한다. CarUxRestrictions 등 실제 안전 신호가 제한 상태이거나 확인되지 않으면 상세 조작과 활동 화면을 중단한다. 기어 P만으로 허용하지 않으며, 수동 시간 모드를 안전 확인을 건너뛰는 경로로 사용하지 않는다.

| 상황 | 기대 동작 |
| --- | --- |
| 현재 잔량이 이미 목표 이상 | 이미 도달했음을 알리고 목표 재설정 또는 종료 선택 |
| 79%에서 81%로 변화 | 정확히 80%인 이벤트가 없어도 목표 도달 감지 |
| 같은 이벤트 반복 | 같은 세션과 목표에 중복 안내하지 않음 |
| 같은 목표 버튼 재선택 | 중복 방지 상태를 초기화하지 않음 |
| 목표 도달 후 잔량이 조금 하락 | 같은 세션의 도달 사실 유지. 안전·데이터 제한은 계속 우선 적용 |
| 목표 전 충전 OFF | 목표 도달과 구분해 중단 또는 상태 변경 안내 |
| 오래된 값, 누락, 연결 해제 | 감시 불가 상태와 마지막 갱신 시각 표시 |
| 안전 상태 불명 또는 주행 제한 | 상세 조작 차단. 안전을 확인한 뒤 다시 평가 |
| 앱 재시작 또는 화면 재생성 | 세션을 복구하되 새 데이터 확인 전 감시 성공 표시 금지 |
| 차량 휴면 상태 | 화면과 오디오를 중단하고 지속 감시 중으로 표시하지 않음 |
| 타이머 종료와 목표 도달이 동시 발생 | 한 번의 결합 안내로 처리 |

관측 시각은 성공한 차량 서비스 읽기의 요청 시각으로 보수적으로 관리한다. UI의 캐시 재표시로 갱신하지 않는다. ON_CHANGE 속성의 원래 변경 시각은 별도로 보존한다. 값이 유지되는 정상 상태를 단지 변경 이벤트가 없다는 이유로 지연 처리하지 않으며, 연결 해제·조회 실패·불가 상태에서는 읽기 성공으로 표시하지 않는다. 서비스 내부 캐시의 실제 센서 신선도는 별도 기기 검증 대상이다.

## 현재 구현 단계

현재 저장소는 **첫 기능 구현 버전**이다. 실제 어댑터를 기본 입력으로 연결했으며 제품 MVP 전체와 실기기 검증이 완성된 상태는 아니다.

| 현재 포함된 것 | 아직 연결하지 않은 것 |
| --- | --- |
| Pleos SOC·capability와 AAOS 충전 상태·UX 제한 읽기 코드 | 실제 권한·값 수신·Console 연동 검증 |
| 목표 70·80·90%와 시간 8·20·40·60분 선택, 카운트다운 | 직접 시간 입력, TTS·오디오 포커스 |
| 자체 휴식·생각 정리·5문항 퀴즈, 완료 확인·중단 흐름 | 콘텐츠 다양화와 기기 조작·가독성 검수 |
| 시간 구간별 직접 선호·명시적 평가·중복 방지·로컬 저장 | 서버 API, 통계적 밴딧·강화학습 |
| 세션 체크포인트와 사용자 확인 복구, 데이터 신선도 재평가 | 기기 재시작·휴면·연결 해제 전체 시나리오 검증 |
| WebView 자체 휴식·YouTube 공식 IFrame 연결과 오류 처리 | Pleos 실제 영상 재생, OTT·휴대폰 인계·외출 추천 |

첫 활동 또는 웹 콘텐츠를 열면 선택한 시간의 카운트다운을 시작한다. 기본 2분의 마무리 여유를 남기며 시간 예산이 부족한 활동을 추천에서 제외한다. debug 전용 시연 모드는 실제 차량 연결과 분리해 명시적으로 표시한다.

단위 테스트, APK 빌드, Pleos 에뮬레이터에서의 설치·프로세스 실행은 확인한 개발 기반이다. 이를 실제 SDK 통합, 실차 동작, 화면·조작 흐름의 시각 검수 완료로 해석하지 않는다.

## MVP 완료 기준

아래 기준은 구현과 검증을 위한 목표이며, 현재 달성한 성과를 뜻하지 않는다.

- 실제 데이터 경로에서 잔량·충전 상태·지원 여부·안전 제한을 받아 정상 및 실패 상태를 구분한다.
- 목표를 건너뛰는 잔량 변화, 반복 이벤트, 목표 도달 후 하락에서 누락이나 중복 없이 처리한다.
- 목표 전 충전 중단, 오래된 값, 권한 거절, 연결 해제를 목표 도달로 표시하지 않는다.
- 시간 입력과 실제 타이머가 작동하며 활동과 마무리 여유가 시간 예산을 넘지 않는다.
- 안전 조건을 확인할 수 없을 때 수동 모드를 포함한 상세 활동을 허용하지 않는다.
- 주행 제한 변경, 휴면, 화면 재생성, 앱 재시작 이후 상태와 안내가 일관되게 복구된다.
- 실제 SDK 입력, 모의 입력, 에뮬레이터 결과, 실차 결과를 구분해 기록한다.

검증 목표는 유효한 목표 교차 이벤트 20회에서 알림 누락·중복 0회, 이벤트 수신 후 안내 요청까지 2초 이내다. 사용자 5명 이상에게 별도 설명 없이 목표·시간 설정을 요청하고 성공 여부와 혼동 지점을 기록한다. 실제 안내 전달 여부는 화면·음성·기기 상태를 함께 확인한다.

## 후속 범위

| 순서 | 기능 | 시작 조건 |
| --- | --- | --- |
| 1 | 지난 활동 다시 시작 | 기본 세션과 로컬 저장이 안정적으로 작동 |
| 2 | 가족용 짧은 활동 | 자체 콘텐츠와 차량 내 사용 방식 검증 |
| 3 | 충전 추세에 따른 시간 범위 | 충분한 관측과 예측 오차 검증 |
| 4 | 휴대폰 세션 전달 | 페어링·테스트 알림·연결 해제 처리 검증 |
| 5 | 외출과 복귀 계획 | 실제 도보 경로·장소 정보·휴대폰 알림 확보 |
| 이후 | 충전 외 주차 대기 상황 | 별도의 시간 종료 조건과 안전한 사용 흐름 정의 |

외출 추천은 **왕복 도보시간 + 활동시간 + 복귀 여유 ≤ 사용 가능한 시간**을 만족해야 한다. 차량 위치를 사용자의 위치로 취급하거나 직선거리를 실제 보행 경로로 표시하지 않는다.

시트·공조·도어·충전 제어, 주문·결제, 장시간 영상, 메일·캘린더 연동, 음성 녹음, 콘텐츠 생성 AI는 초기 범위에서 제외한다. 사용자의 반복 이용을 확인한 뒤 필요한 제휴와 수익 모델을 검증한다.

## 다음 개발 순서

1. 에뮬레이터의 권한·실제 데이터·주행 제한 변경부터 앱 안내까지 통합 검증.
2. 전체·분할 창 UI, 자체 활동과 세션 복구, YouTube 실제 재생 검수.
3. TTS와 오디오 포커스, 오류·휴면·복구 흐름 통합.
4. 장소·도보 경로 제공사 및 휴대폰 인계 검증 후 외출 기능 추가.
5. 자체 콘텐츠 확장과 시간별 개인화 사용성 평가.
6. 사용자 테스트 후 공모전 시연 범위와 제출 자료 확정.

개발 중 범위를 바꿀 때는 이 문서의 MVP, 완료 기준, 현재 구현 단계를 함께 갱신한다. 제안 기능을 구현 완료 기능으로 표현하지 않는다.
