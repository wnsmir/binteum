# 웨이팅 구현·검증 기록

## 주변 장소·측면 메뉴 겹침 수정 — 2026-11-15

기존 콘텐츠는 82dp만 비워 두었으나 메뉴는 펼쳐진 글자까지 더 넓게 측정돼 세 번째 장소 카드와 겹쳤다. 이제 `DockContentLayout`이 메뉴의 실제 폭과 8dp 간격을 제외한 영역에 콘텐츠를 배치한다. 좌우 설정 모두 같은 방식을 사용하며, 패널 이동 애니메이션도 메뉴와 콘텐츠의 공통 호스트에 적용한다.

메뉴 이름은 항상 표시하고 선택 시 배경만 바꾼다. 좁은 콘텐츠 영역에서는 기본 104dp 폭의 아이콘 위·이름 아래 형태로, 충분히 넓으면 아이콘 옆 이름으로 배치한다. 글자 확대를 반영하고 두 줄 이름을 허용한다. 콘텐츠/미디어 객체 보존과 스크롤 갱신 경로는 유지한다.

검증: debug 빌드 성공, lint 오류 0개·경고 70개. `DockHitTestProbe`는 좌우·480/900/1400dp·글자 100/130%·한/영의 24개 조합, 688개 배치/터치 검사를 통과했다. `WaitingFlowProbe` 61개 검사도 통과했다. `DockLayoutCaptureProbe`로 실제 앱을 130% 글자에서 라이트·오른쪽, 다크·오른쪽, 다크·왼쪽으로 캡처해 카드 3열 유지와 메뉴 겹침이 없음을 확인했다. 캡처의 카페 3곳은 명시적 배치 검증용 예시이며 실제 장소 검색 증거가 아니다.

## 현재 에뮬레이터 위치 권한 복구 — 2026-11-15

현재 Mac의 운전자 프로필(user 10)에서 기존 `com.binteum.app`은 위치 권한이 있었지만, 별도 debug 앱 `com.binteum.app.friend`는 미허용이었다. 사용자 승인 후 새 앱의 `FUSED_LOCATION` 하나만 부여했다. Pleos 2.1 권한 창 대신 표시되는 안내는 실제 권한 부여가 아니므로, 별도 패키지 설치 시 개발 환경 설정이 다시 필요할 수 있다.

현재 GPS를 바꾸지 않은 첫 진단은 최신 SDK 위치 수신과 검색 응답에 성공했으나 `OUTSIDE_COVERAGE`로 장소 0건이었다. 이후 에뮬레이터 GPS를 공개 강남역 시험 위치로 설정해 실제 SDK → 로컬 서버 → OSM/Valhalla 경로를 다시 확인했다. 결과는 `WITHIN_COVERAGE`, 장소 3곳, 왕복 경로 3건이다. 앱을 다시 실행했다. 실제 사용자·Mac·실차의 위치 검증은 아니다.

`NearbySdkIntegrationProbe`는 기본 강남역 시험 검사를 유지하며, 명시적 실행 인자 `-e useCurrentEmulatorLocation true`에서만 이미 설정된 에뮬레이터 위치로 진단한다. 이 옵션은 GPS나 권한을 바꾸지 않고 좌표를 출력하지 않는다. 빈 정상 응답은 `NO_PLACE_RECOMMENDATIONS`와 coverage로 표시해 서버 연결 성공과 장소 추천 성공을 구분한다. 테스트 APK 빌드 및 두 진단 경로 실행을 확인했다.

## 영상 서비스 선택 — 2026-11-15

영상 제목과 같은 행에 YouTube로 이동·Netflix로 이동을 배치하고, 그 아래 컬러 아이콘을 가진 가로 선택 메뉴를 추가했다. YouTube 선택에서는 기존 영상 카드·인라인 플레이어를 유지한다. Netflix 선택에서는 외부 서비스 안내를 제공한다. 선택 변경 시 유튜브 플레이어를 정지/해제하며, 다시 돌아와도 자동 재생하지 않는다.

외부 이동은 공식 앱 → 일반 브라우저 → 휴대폰 QR 순서다. 로그인용 브라우저가 아닌 에뮬레이터 WebViewShell은 제외한다. 직접 재생·로그인 성공으로 기록하지 않으며, Netflix 임베드 재생은 추가하지 않았다. 음악 선택은 기존 대화상자 흐름을 유지한다.

검증: debug 빌드 성공, lint 오류 0개·경고 65개. WaitingFlowProbe **61개**(새 서비스 선택·숨겨진 플레이어 차단 포함), VideoServicesProbe **16개**(가짜 외부 실행 대상으로 URL·실행 순서·차단 검사) 통과. 에뮬레이터에 업데이트 설치했다. 이 검사는 실제 외부 로그인·Netflix 스트리밍 검증이 아니다.

## 최신 패치 — 2026-11-15

`origin/main`의 `fa719f1`을 기준으로 `codex/waiting-integration-patch`에서 통합 화면의 회귀를 수정했다. 웨이팅의 스크롤 화면, 측면 메뉴, 단순 수면 UI 및 별도 debug 패키지를 유지한다.

- 짧거나 끝난 대기시간에도 영상 직접 선택 가능. 시간 적합 안내와 차량 안전 차단은 유지.
- 주변 장소의 다른 종류/뒤로가기에서 해당 섹션으로 복귀. 열린 영상은 뒤로가기로 먼저 닫음.
- 접힌 측면 메뉴의 투명한 글자 영역이 뒤쪽 카드 터치를 가로채지 않음. 레이아웃 크기는 유지.
- 대기시간의 저장 상태를 같은 프로세스에서만 복원해 재시작 후 오래된 타이머가 다시 시작되는 문제 방지.
- 선택 기록에 실제 사용 가능 시간을 추가하고, 차량 ETA·출처를 별도 보존. 수동 시간·출발 제한을 반영한 시간 구간으로 선호 표시. SQLite v1→v2는 기존 기록을 보존하며 과거에 없던 수동 시간을 만들어내지 않음.

검증: core **92개**, 서버 **16개**, 통합 화면 **53개**, 영상 직접 선택/안전 차단 **36개**, 메뉴 터치 **12개**, SQLite 저장/마이그레이션 **19개** 통과. debug APK 및 테스트 APK 빌드 성공, lint 오류 **0개**·경고 **63개**. Pleos 에뮬레이터의 현재 운전자 user 10에 `com.binteum.app.friend` 업데이트 설치. 위치 검색용 로컬 서버 health와 adb reverse 연결도 확인했다.

화면 검사는 모의 차량 상태 또는 분리된 View fixture 기반이다. 이번 패치 검증에서 실제 음악 로그인·영상 재생·GPS 경로·시트 이동을 새로 수행하지 않았으며, 그 기능의 기존 한계를 해소했다는 의미는 아니다. 실행 검사는 `-PbinteumTestRunner=com.binteum.app.<ProbeName>`으로 테스트 APK를 빌드한 뒤 해당 instrumentation을 실행했다.

## 이전 통합 상태 — 2026-11-14

현재 브랜치 `codex/unified-waiting-flow`, 별도 설치 패키지 `com.binteum.app.friend`. 아래 날짜별 기록은 당시 버전이며 현재 기능 목록을 대신하지 않는다. 실행 절차는 [README](../README.md), SDK 전체는 [연동 현황](sdk-integration.md), 제출용 소개는 [문안](design/waiting-submission-outline.txt)을 따른다.

- 표시 이름: 한국어 웨이팅, 영어 Waiting. 비교 설치용 debug는 웨이팅 · 친구 / Waiting · Friend. 패키지·설정·기록 보존.
- 수면 섹션: 남은 시간 동안 수면 / 시트 위치 설정 두 버튼만 유지. 준비 시간 없이 현재 이용 가능 시간 전체 사용. 수면 중 검은 앱 화면에 카운트다운과 종료 버튼만 표시. 종료 시 화면·스크롤·밝기 복원, 메인 타이머 유지.
- 현재 UI에서 공조·온도·배경음·기상 준비 설정 제거. 기존 backend 코드가 있다는 이유로 현재 제공 기능으로 소개하지 않음.
- 시트: 기존 앞좌석 왼쪽 메모리 선택·기억·명시적 적용 요청. 새 자세 저장 API 및 적용 완료 readback 없음. 지원 응답 WRITE, ROW_1_LEFT 1..2 확인. 실제 이동 미검증.
- 위치 문제: Pleos Connect 2.1.0 ARM64의 ungrouped FUSED_LOCATION 권한 팝업이 검은 글자/검은 배경으로 표시돼 앱을 가리는 현상 관찰. 앱 ANR로 확인된 것은 아님. 해당 이미지에서 문제 팝업 대신 안내 표시, 정상 기기는 공식 runtime 요청 유지.
- 사용자의 명시적 동의 후 실제 current user를 확인하고 user 10의 com.binteum.app.friend에 FUSED_LOCATION 하나만 adb로 허용. Mac 위치 권한 변경 없음.
- 공개 강남역 시험 GPS를 에뮬레이터에 설정. 실제 FusedLocation SDK에서 fresh fix 수신 → 실제 Android 클라이언트 → 로컬 BFF → OSM/Valhalla 조회 성공. 장소 3곳·왕복 경로 3건. 실제 차량 위치 또는 모의 충전이 실제 충전임을 의미하지 않음.
- 음악: 지원 서비스 앱 3개·일반 브라우저 없음 확인, QR 경로 제공. 로그인·실제 스트리밍 미검증.
- YouTube 임베드 구현은 존재하나 현재 버전의 실제 영상/소리 재검수 미완료. Pleos TTS 실제 소리도 미확인. Gleo 자동 알림 완료로 소개하지 않음.

### 실제 수행 검사

- core 87개 통과, APK 빌드 성공, lint 오류 0개·경고 63개.
- WaitingFlowProbe 48개 통과: 모의 차량 주입 기반 예산·화면·안전 제한·수면 화면·종료 복귀. 실제 차량 쓰기 없음.

- 서버 단위 검사 16개 통과. README의 POI 준비 명령으로 프로젝트 전용 venv 설치 및 공식 지도 캐시에서 실제 POI 119,684개 생성. 원본 다운로드는 기존 공식 캐시 재사용. 생성된 기본 경로 인덱스로 서버 재시작.

- SeatMemoryGuardProbe 10개, MusicIntegrationProbe 40개는 앞선 동일 구현 검사 기록. 가짜 Seat 안전 경계 및 외부 연결 조건 검사이며 계정·모터에 접근하지 않음.
- ReadmeDemoProbe 13개 통과: 정상 debug 모의 충전 소스, 실제 UI 버튼과 단조 시계 ticker로 설정→타이머→수면→종료→설정 적용 실행. 테스트에서 차량/시간 상태를 주입하지 않음. 시연용 수면 선택 1건 기록. 앱 코드 크래시는 없으며 초기 테스트의 잘못된 클릭 대상/null 탐색을 수정한 뒤 통과.

## 제출용 화면 자료 — 2026-11-14

[실제 화면 사용 안내](design/waiting-screen-guide.pdf)는 현재 APK에서 새로 캡처한 9개 화면을 사용한다. 홈·타이머·진행·음악·음악 선택·주변 장소·수면 진입·검은 수면 화면·설정을 포함한다. SOC 65%와 20분은 명시적 모의 시연 값이다. 화면 자체를 재디자인하지 않았으며, 페이지 밖에 사용 순서와 현재 이용 범위를 설명했다. 실제 미디어 재생·시트 이동·음성 출력의 성공 증거로 사용하지 않는다. 기존 와이어프레임 PDF는 별도 구조 참고 자료로 보존한다.

## 활동 화면 통합 — 2026-11-12

활동 탭을 카페·식사·간식·산책의 현재 위치 검색으로 통합했다. 하단은 대시보드·영상·음악·활동·낮잠 다섯 탭이다. 기존 자체 활동 목록과 추천, 진행/복구 화면은 진입 경로에서 제거했다. 이전 탭 번호는 통합 활동 화면으로 옮기고, 이전 자체 활동 체크포인트만 제거해 업데이트 뒤 다시 나타나지 않도록 했다. 기존 SQLite 선택 이력은 유지한다. 위치 조회·권한 재개·취소·지도 인계는 기존 주변 화면의 내부 경로를 사용한다.

아래 이전 구현 시점의 자체 활동·별도 주변 탭 설명은 현재 화면 구성에 적용하지 않는다.

검증: debug 빌드 성공, lint 오류 0개·경고 47개, 에뮬레이터에 최신 APK 설치·Activity 실행 완료. 자체 활동 목록·추천 진입 및 기존 체크포인트 복구 호출이 제거됐음을 코드에서 확인했다. 위치·경로 API는 변경하지 않았다.

읽기 전용 `LocationCapabilityProbe`에서는 차량 위치 서비스 지원을 확인했으나 위치 권한이 아직 없어 실제 위치 조회는 건너뛰었다. 최신 앱 설치·Activity 실행을 완료했으며 사용자에게 카테고리 선택→정상 OS 위치 권한 승인→자동 검색 화면 확인을 요청했다. 실제 차량 위치 수신·장소 카드 배치·QR 스캔은 아직 확인 완료로 기록하지 않는다. 직전 지도 링크 버전의 SQLite 8개·NearbyMapProbe 13개 통과 기록은 별도 이전 검증이다. 낮잠 기상음·차량 쓰기·주행/충전 상태 전환 검수도 별개다.

주변 검색 서버는 `server/src/index.mjs`에서 loopback `127.0.0.1:3210`으로만 실행한다. Debug 앱은 `adb reverse tcp:3210 tcp:3210`으로 연결하며 Release에는 별도 HTTPS 주소가 필요하다. Kakao 로그인은 진행하지 않았다. Geofabrik의 2026-11-08T21:21:00Z 한국 지도 원본을 공식 체크섬으로 확인하고 실제 POI 119,663개(카페 12,589·음식점 81,459·편의점 15,968·공원 9,647)를 추출했다. 인덱스 27.27MB와 원본·의존성은 `.local/maps/`에 저장하고 Git에서 제외한다. 한국 지원 범위 밖은 별도로 표시한다. 보행 경로에는 Valhalla를 사용하며 공개 Overpass timeout 때문에 기본값에서 제외했다. 위치·장소는 개인화 DB나 일반 로그에 남기지 않으며 서버의 메모리 캐시는 최대 60초·8개 항목으로 제한한다.

공조의 읽기 전용 진단에서는 Pleos 공조/시트 권한과 온도 READ_WRITE, 앞좌석 2개 구역의 15–30°C·0.5°C 간격 지원을 확인했다. 현재 공조 전원은 false였고, 온도 getter는 HVAC_TEMPERATURE_SET의 PropertyNotAvailableException을 반환했다. Android CAR_SPEED 권한도 아직 허용되지 않았다. 현재 값·P단/속도를 검증하기 전 실제 온도 쓰기와 복원은 비활성이며, 이 점검에서 차량 쓰기는 하지 않았다. 실제 차량 ETA·목표 쓰기·위치 수신도 별도 검증 대상이다. 현재 APK는 개발용 debug이며 제출용 release가 아니다.

확인 명령은 `./scripts/gradle.sh :core:test :app:assembleDebug :app:lintDebug --no-daemon`이다. 결과 경로는 `core/build/reports/tests/test/index.html`, `app/build/reports/lint-results-debug.html`, `app/build/outputs/apk/debug/app-debug.apk`다.

로컬 기록 검사(전용 테스트 DB만 사용, 사용자 기록·차량 설정 변경 없음):

위치 지원 진단은 `-PbinteumTestRunner=com.binteum.app.LocationCapabilityProbe`로 수행한다. 서비스·권한·원본 위치 freshness만 보고하며 좌표 자체나 원시 timestamp를 출력하지 않는다. 테스트 실행만으로 위치 권한을 허용하지 않는다.

지도 경계 검사는 `-PbinteumTestRunner=com.binteum.app.NearbyMapProbe`로 테스트 APK를 빌드하고 해당 runner를 실행한다. 네트워크·실제 위치 조회·외부 UI 실행은 하지 않는다. 기존 TTS 진단은 `-PbinteumTestRunner=com.binteum.app.TtsSdkProbe`로 별도 실행하며 이번 검사에 포함하지 않았다.

## UI 참고와 적용

[Tesla Model Y 공식 터치스크린 설명](https://www.tesla.com/ownersmanual/modely/en_sg/GUID-518C51C1-E9AC-4A68-AE12-07F4FF8C881E.html)의 차량 상태 영역, 주 콘텐츠 영역, 하단 앱 접근 구조를 참고했다. 이후 화면 고도화에서 자동차 장식을 SOC 게이지로 바꾸고, 오프화이트/차콜 테마·라임 강조·공통 선형 아이콘을 적용했다. Tesla 로고나 차량 이미지를 사용하지 않았다.

[Tesla Theater 안내](https://www.tesla.com/ownersmanual/modely/en_us/GUID-79A49D40-A028-435B-A7F6-8E48846AB9E9.html)는 차량 엔터테인먼트 흐름의 참고 자료다. Pleos에서의 허용 여부는 Pleos/AAOS UX 제한으로 판단하며 Tesla의 지원 서비스를 Pleos에서도 지원한다고 가정하지 않는다.

## 차량 API 조사 결과

[전체 API 매트릭스](vehicle-api-matrix.md)에 공모전이 연결한 5개 SDK와 Vehicle의 19개 영역을 정리했다. Vehicle 2.3.2 소스와 AAR에서 공식 공개 분류에 해당하는 메서드는 440개였다. 공식 샘플의 442개 안내와 차이를 기록했으며, 모든 메서드의 권한·읽기/제어/구독·앱 연결 여부를 구분했다.

이 절의 2026-11-08 버전은 읽기만 수행했다. 충전 시작 요청 스위치와 실제 충전 상태는 다른 값이다. 실제 충전은 AAOS `EV_CHARGE_STATE`로 판단하며, 스위치만으로 충전 중이라 표시하지 않는다. UX 상태 미확인·제한, 서비스 실패·미지원, 데이터 지연에서는 활동을 열지 않는다. 실제 기어 P 입력은 연결하지 않았다. `vehicleAwake`는 현재 디바이스의 interactive 상태이며 차량 IGN 신호가 아니다.

ON_CHANGE 데이터는 값이 유지되면 변경 시각이 오래될 수 있다. 새 서비스 조회의 성공과 연결 상태를 확인하고 요청 시각을 관측 시각으로 쓰며, 원본 변경 시각은 별도 진단값으로 보존한다. 화면이 다시 그려졌다는 이유로 관측 시각을 갱신하지 않는다. 서비스 내부 캐시가 센서 값을 얼마나 최신으로 유지하는지는 기기 검증 대상이다.

## 권한 문제 수정과 실제 경로 확인

사용자 화면에 SOC 100%와 `AAOS CAR_ENERGY 권한 없음`이 함께 나타났다. SOC는 Pleos 권한으로 읽혔으나 실제 충전 상태용 Android 런타임 권한은 별도였다. 이 에뮬레이터의 활성 운전자 프로필은 `am get-current-user` 기준 10이며 앱도 user 10에서 실행 중이었다. 해당 프로필에 `android.car.permission.CAR_ENERGY`를 허용하고 다음 앱 로그를 확인했다.

| 입력/관찰 | SDK·AAOS 반환 | 앱 판단 |
| --- | --- | --- |
| 최초 실제 연결 | SOC 100, charge switch false, `STATE_FULLY_CHARGED`, UX restricted false | 목표 80% 도달 |
| 공식 Console의 Battery SOC를 65로 변경 | SOC 65 수신, 실제 충전 상태는 여전히 `STATE_FULLY_CHARGED` | 이미 도달한 세션의 목표 기록 유지 |
| 공식 Console의 Charge Switch를 On으로 변경 | charge switch true 수신, 실제 충전 상태는 여전히 `STATE_FULLY_CHARGED` | 스위치 true를 실제 충전으로 간주하지 않음 |

따라서 이 설정에서 충전 중 전환은 아직 검증하지 못했다. 실제 SDK 경로의 반환값과 명시적 시연 모드를 구분한다. 일반 AOSP `cmd car_service`의 일부 debug 명령도 이 user 이미지에서는 거부된다. 주행 제한을 우회하거나 차량 읽기 값을 강제로 정상으로 취급하지 않는다.

권한이 없을 때 활동과 미디어 화면에 직접 허용 버튼을 추가했다. 권한 거부 후에는 앱 설정 경로를 제공하며 연결 실패는 재확인할 수 있다. SOC·충전 요청 스위치·실제 충전 상태 진단을 분리하고, 기술 문구는 개발용 설정 화면으로 옮겼다. debug 전용 시연 버튼으로 실제 연결과 구분해 콘텐츠를 확인할 수 있다.

보고서 위치: `core/build/reports/tests/test/index.html`, `app/build/reports/lint-results-debug.html`. APK: `app/build/outputs/apk/debug/app-debug.apk`. 산출물·로그·캐시는 `.gitignore`로 제외한다.

## 다음 통합 검수 순서

1. 앱 화면의 `충전 상태 읽기 허용` 경로에서 거부·다시 허용·프로필 변경을 추가 검수한다. 현재 활성 프로필의 권한은 허용했으며 최초 권한 누락과 허용 뒤 실제 수신을 확인했다.
2. Virtual Console에서 실제 SOC·충전 상태·UX 제한을 바꿔 앱 표시와 차단을 검사한다. 실제 충전 상태 미지원이면 진단을 남기고 해당 값을 추정으로 대체하지 않는다.
3. debug의 명시적 시연 모드로 자체 활동, 퀴즈·평가, 시간 경계, 목표 도달 후 새 세션, 앱 이탈·복구를 검수한다. 모의 결과는 실제 API 검증과 별도 기록한다.
4. 웹 콘텐츠부터 열었을 때 시간 선택이 잠기고 타이머가 시작되는지, 새 대기 시간을 설정하면 기존 웹 콘텐츠가 닫히는지 검사한다.
5. YouTube 공식 예제의 영상·소리 재생은 사용자가 확인했다. 자체 웹 휴식 60초 완료와 영상 재생 중 목표 도달·충전 중단·UX 제한·앱 이탈 시 화면과 음성 중지를 추가 검사한다.
6. TTS/오디오 포커스를 연결한 뒤 차량 안 시연을 확정한다. 다음으로 장소·왕복 도보 경로와 휴대폰 인계를 구현한다.

이 절의 2026-11-08 버전에는 주변 산책·간식 추천, Netflix, 외부 콘텐츠 검색, BFF 서버, 휴대폰 알림, Gleo가 포함되지 않았다. 이후 Netflix 외부 연결과 현재 기능 범위는 상단 및 UI 변경 기록을 따른다. API 명세의 서버 경로는 설계 계약이며 실행 중인 서버가 아니다.
