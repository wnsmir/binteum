기준일: 2026-11-08. 기능 기반: `codex/charging-experience`; 화면 고도화: `codex/ui-refinement`. 이 기록은 구현한 코드와 확인한 실행 결과를 구분한다. 현재 APK는 개발용 debug 빌드이며 공모전 제출용 release 산출물이 아니다.

## UI 참고와 적용

[Tesla Model Y 공식 터치스크린 설명](https://www.tesla.com/ownersmanual/modely/en_sg/GUID-518C51C1-E9AC-4A68-AE12-07F4FF8C881E.html)의 차량 상태 영역, 주 콘텐츠 영역, 하단 앱 접근 구조를 참고했다. 이후 화면 고도화에서 자동차 장식을 SOC 게이지로 바꾸고, 오프화이트/차콜 테마·라임 강조·공통 선형 아이콘을 적용했다. Tesla 로고나 차량 이미지를 사용하지 않았다.

[Tesla Theater 안내](https://www.tesla.com/ownersmanual/modely/en_us/GUID-79A49D40-A028-435B-A7F6-8E48846AB9E9.html)는 차량 엔터테인먼트 흐름의 참고 자료다. Pleos에서의 허용 여부는 Pleos/AAOS UX 제한으로 판단하며 Tesla의 지원 서비스를 Pleos에서도 지원한다고 가정하지 않는다.

## 차량 API 조사 결과

[전체 API 매트릭스](vehicle-api-matrix.md)에 공모전이 연결한 5개 SDK와 Vehicle의 19개 영역을 정리했다. Vehicle 2.3.2 소스와 AAR에서 공식 공개 분류에 해당하는 메서드는 440개였다. 공식 샘플의 442개 안내와 차이를 기록했으며, 모든 메서드의 권한·읽기/제어/구독·앱 연결 여부를 구분했다.

현재 앱은 읽기만 수행한다. 충전 시작 요청 스위치와 실제 충전 상태는 다른 값이다. 실제 충전은 AAOS `EV_CHARGE_STATE`로 판단하며, 스위치만으로 충전 중이라 표시하지 않는다. UX 상태 미확인·제한, 서비스 실패·미지원, 데이터 지연에서는 활동을 열지 않는다. 실제 기어 P 입력은 연결하지 않았다. `vehicleAwake`는 현재 디바이스의 interactive 상태이며 차량 IGN 신호가 아니다.

ON_CHANGE 데이터는 값이 유지되면 변경 시각이 오래될 수 있다. 새 서비스 조회의 성공과 연결 상태를 확인하고 요청 시각을 관측 시각으로 쓰며, 원본 변경 시각은 별도 진단값으로 보존한다. 화면이 다시 그려졌다는 이유로 관측 시각을 갱신하지 않는다. 서비스 내부 캐시가 센서 값을 얼마나 최신으로 유지하는지는 기기 검증 대상이다.

## 로컬 검증

실행 명령:

```bash
./scripts/gradle.sh :core:test :app:assembleDebug :app:lintDebug --no-daemon
```

- JBR 21 / SDK 34 환경에서 최종 통합 빌드 성공.
- core 테스트 **23개, 실패 0개, 오류 0개**. 기존 충전 상태 9개와 신규 활동·추천·평가 14개.
- lint **오류 0개, 경고 3개**. 고정 SDK/AGP/의존성의 최신 버전 안내다.
- 두 HTML의 JavaScript 구문 검사 통과.
- Pleos API 34 ARM64 에뮬레이터에서 debug APK 설치와 Activity 실행을 확인했다.
- 독립 Qt 에뮬레이터 창이 현재 UI 제어 도구에서 인식되지 않았다. 사용자가 제공한 세 화면에서 UI와 권한 누락 안내를 확인했고, 이후 사용자가 시연 모드의 활동 카드 노출 및 YouTube 영상·소리 정상 재생을 직접 확인했다. 전체 화면·조작 검수 완료로 확대하지 않는다.

## 권한 문제 수정과 실제 경로 확인

사용자 화면에 SOC 100%와 `AAOS CAR_ENERGY 권한 없음`이 함께 나타났다. SOC는 Pleos 권한으로 읽혔으나 실제 충전 상태용 Android 런타임 권한은 별도였다. 이 에뮬레이터의 활성 운전자 프로필은 `am get-current-user` 기준 10이며 앱도 user 10에서 실행 중이었다. 해당 프로필에 `android.car.permission.CAR_ENERGY`를 허용하고 다음 앱 로그를 확인했다.

| 입력/관찰 | SDK·AAOS 반환 | 앱 판단 |
| --- | --- | --- |
| 최초 실제 연결 | SOC 100, charge switch false, `STATE_FULLY_CHARGED`, UX restricted false | 목표 80% 도달 |
| 공식 Console의 Battery SOC를 65로 변경 | SOC 65 수신, 실제 충전 상태는 여전히 `STATE_FULLY_CHARGED` | 이미 도달한 세션의 목표 기록 유지 |
| 공식 Console의 Charge Switch를 On으로 변경 | charge switch true 수신, 실제 충전 상태는 여전히 `STATE_FULLY_CHARGED` | 스위치 true를 실제 충전으로 간주하지 않음 |

따라서 이 설정에서 충전 중 전환은 아직 검증하지 못했다. 실제 SDK 경로의 반환값과 명시적 시연 모드를 구분한다. 일반 AOSP `cmd car_service`의 일부 debug 명령도 이 user 이미지에서는 거부된다. 주행 제한을 우회하거나 차량 읽기 값을 강제로 정상으로 취급하지 않는다.

권한이 없을 때 활동과 미디어 화면에 직접 허용 버튼을 추가했다. 권한 거부 후에는 앱 설정 경로를 제공하며 연결 실패는 재확인할 수 있다. SOC·충전 요청 스위치·실제 충전 상태 진단을 분리하고, 기술 문구는 개발용 설정 화면으로 옮겼다. debug 전용 시연 버튼으로 실제 연결과 구분해 콘텐츠를 확인할 수 있다.

보고서 위치: `core/build/reports/tests/test/index.html`, `app/build/reports/lint-results-debug.html`. APK: `app/build/outputs/apk/debug/app-debug.apk`. 산출물·로그·캐시는 `.gitignore`로 제외한다.

## 다음 통합 검수 순서

1. 앱 화면의 `충전 상태 읽기 허용` 경로에서 거부·다시 허용·프로필 변경을 추가 검수한다. 현재 활성 프로필의 권한은 허용했으며 최초 권한 누락과 허용 뒤 실제 수신을 확인했다.
2. Virtual Console에서 실제 SOC·충전 상태·UX 제한을 바꿔 앱 표시와 차단을 검사한다. 실제 충전 상태 미지원이면 진단을 남기고 해당 값을 추정으로 대체하지 않는다.
3. debug의 명시적 시연 모드로 자체 활동, 퀴즈·평가, 시간 경계, 목표 도달 후 새 세션, 앱 이탈·복구를 검수한다. 모의 결과는 실제 API 검증과 별도 기록한다.
4. 웹 콘텐츠부터 열었을 때 시간 선택이 잠기고 타이머가 시작되는지, 새 대기 시간을 설정하면 기존 웹 콘텐츠가 닫히는지 검사한다.
5. YouTube 공식 예제의 영상·소리 재생은 사용자가 확인했다. 자체 웹 휴식 60초 완료와 영상 재생 중 목표 도달·충전 중단·UX 제한·앱 이탈 시 화면과 음성 중지를 추가 검사한다.
6. TTS/오디오 포커스를 연결한 뒤 차량 안 시연을 확정한다. 다음으로 장소·왕복 도보 경로와 휴대폰 인계를 구현한다.

주변 산책·간식 추천, Netflix, 외부 콘텐츠 검색, BFF 서버, 휴대폰 알림, Gleo는 이번 구현에 포함되지 않았다. API 명세의 서버 경로는 설계 계약이며 실행 중인 서버가 아니다.
